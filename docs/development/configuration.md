# Environment Variables and Flags

**Every setting the server reads, where it is read, and the bounds and register rows behind it**: the contributor's view of configuration.

> **Diátaxis type**: Reference · **Audience**: 🛠️ Contributors & maintainers

The user-facing references are the site's [environment variables](https://docs.jmrp.io/gitlab-mcp-server/reference/environment/) and [CLI](https://docs.jmrp.io/gitlab-mcp-server/reference/cli/) pages. This page adds what a contributor needs on top of them: the Go symbol that reads each setting, the tenant policy row that decides a bound, and the rule a new setting follows. A change of configuration updates those pages in both languages, the lists below, the summary table in `CLAUDE.md`, and the environment variable and flag tables in `.github/copilot-instructions.md`.

---

Settings this project defines are read as `GITLAB_MCP_<NAME>` and under no
other spelling, apart from the three groups below that stay bare. The rule
for a new setting is that it is added to
`prefixedNames` in `internal/config/env_name.go` and read through
`config.Getenv` or `config.TrimmedGetenv` there, never through `os.Getenv`.
Every variable the server defines follows it but one, `ENV_FILE`, which names
the dotenv file to load and is read once from the process environment before
any file is loaded (`internal/config/env_file.go`), so a file this server
declines to load cannot nominate itself. The twelve others issue 957 found read
around the list, the listen and stdio line ceilings, the five `TELEMETRY*`
variables, the three `ALLOWED_*_DIRS`, `ALLOW_PRIVATE_INSTANCES` and
`DESCRIPTION_SUBSTITUTIONS`, are on it since then, read under the same
spelling, and none of them has an old spelling for `config.RetiredEnvUses` to
report. `make check-tenancy` holds it (rule G14): every `GITLAB_MCP_` variable
the server reads any other way is answered by the register row that names it,
which would have to carry F-13, or by a declaration in
`cmd/audit_tenancy/declarations.go` with its reason, which is how `ENV_FILE` is
answered. A variable read that way that no row names and no declaration
answers fails the gate, and so does one a row without F-13 names.
So does a name handed to `config.Getenv` that the list does not hold, which it
reads bare, unless a declaration there says the name is somebody else's, as
the one for `GITLAB_URL` does: a setting moved onto `config.Getenv` and left
off the list would otherwise be read under a name no operator sets.

Every variable this server defines carries the prefix, with no exception for
a name that already began with `GITLAB_`: the switches that did (`GITLAB_TIER`,
`GITLAB_READ_ONLY`, `GITLAB_SAFE_MODE`, `GITLAB_IGNORE_SCOPES`,
`GITLAB_SKIP_TLS_VERIFY`) and `YOLO_MODE` were renamed in 3.0.0, and their old
spellings were removed in 3.1.0. `config.RetiredEnvUses` finds one still set in
the environment so a deployment is told rather than quietly reconfigured, and
splits its answer: `GITLAB_READ_ONLY`, `GITLAB_SAFE_MODE` and `EXCLUDE_TOOLS`
(`config.protectionNames`, the three settings register row `AUT-004` decides)
**refuse startup**, because ignoring one in silence serves writes, or the
actions an operator removed, on a deployment that asked for neither, and every
other retired name is a warning. The condition is what ignoring one would cost,
not where it came from: the refusal reads the name and never its value, and a
bare `EXCLUDE_TOOLS` refuses even though another tool in the same shell could
own it, since the server cannot tell whose it is and guessing that it is
somebody else's is the guess that serves what was removed. Only the 28
settings 3.0.0 read had an old spelling, and `config.hadOldSpelling` is that
closed list: a setting added since, from the four authentication budgets of
3.1.0 on, carries the prefix from its first day, needs no entry there, and
its bare suffix is never reported.
Only three groups stay bare, because prefixing them
would be wrong rather than churn: `GITLAB_URL` and `GITLAB_TOKEN` (GitLab's own
convention, and what a user already has in the environment, so they are never
spelled twice), every `OTEL_*` variable (owned by the OpenTelemetry
specification and read by the exporters themselves), and `AUTOPILOT` (a
convention other agent tooling sets, honored as an alias of
`GITLAB_MCP_YOLO_MODE` and never warned about). The model evaluation's
`MODELEVAL_*`
and the test transport's `GITLAB_MCP_TEST_INVENTORY_DIR` are developer-only,
driven by `make` targets, read by test code that `cmd/server` never links, and
out of scope: they configure the harness rather than the server, and there is
no legacy spelling of either to warn anybody about.

## Variables

A duration variable whose zero turns its setting off reads a zero however it
is written, `0`, `0s` or `0h0m0s`, as the flag of the same name does
(`config.parseDisableableDurationEnv`, issue 958): the session timeout, the
revalidation interval, the pool idle timeout, the action timeout, the drain
delay and the two authentication windows. A negative duration is refused,
since zero already says off. The OAuth cache TTL is the one duration whose zero
is refused, by the flag and the variable alike and in either authentication
mode (register row `ADM-005`, `refuseNonPositiveOAuthCacheTTL`); its range is
checked in oauth mode only, where the TTL is used.

A stdio server reads only the variables of the settings it has. The sixteen of
a setting only HTTP mode has, the listener's plain HTTP opt-in, the pool, the
stateful session, the drain, the authentication gate with its budgets, the OAuth verifier and its metadata, the
trusted origins and the discovery bucket, are listed in `config.httpOnlyNames`:
`config.Load` reads none of them and leaves their fields zero, the HTTP overlay
is their one reader, and a stdio run names each one its environment sets in one
line, at WARN and at INFO under `--transport=auto`, and serves whatever their
values (`config.HTTPOnlyEnvUses`, `reportStdioIgnoredVariables` in
`cmd/server/http_only_flags.go`, issue 1171). Load used to parse most of them
and refuse to start on a value it would never use, so a variable exported for an
HTTP deployment in the same shell stopped a stdio server.
`TestHTTPOnlyNames_AreTheSettingsOnlyTheOverlayReads` holds the list to the two
readers by what each does, so a setting HTTP mode gains is on it, and one stdio
starts reading leaves it. The revalidation interval is not one of them: stdio
re-reads a fine-grained token at it.

- **`GITLAB_URL`** (required on stdio): GitLab instance URL (e.g., `https://gitlab.example.com`). In HTTP mode it is `--gitlab-url`, which is **required** unless `--allow-any-gitlab-url` is passed, and the count decides the header's meaning: none (with the escape hatch) lets `GITLAB-URL` select freely per request, and a request that omits it is refused rather than resolved to `https://gitlab.com`; exactly one fixes the instance and the header is ignored; several publish an allow-list among which the header is required, since choosing for the caller would send their token to an instance they never named. A comma-separated value spells the list
- **`GITLAB_TOKEN`** (required on stdio): Personal Access Token (`glpat-...`): a classic one, or a fine-grained one whose grant decides what it is served ([guide](https://docs.jmrp.io/gitlab-mcp-server/operations/fine-grained-tokens/))
- **`GITLAB_MCP_SKIP_TLS_VERIFY`** (optional): Skip TLS verification for self-signed certs (`true`)
- **`GITLAB_MCP_ENV_FILE`** (optional): One dotenv file to load besides `~/.gitlab-mcp-server.env`, resolved **once** from the process environment before any loaded file could rewrite it, so a file this server loads cannot nominate another. Precedence, highest first: the process environment, this file, the home file. A working-directory `.env` is not loaded at all, only found and named at WARN with the keys it wanted to set. Give an absolute path: a relative one follows the client into every workspace it opens, which is the load this replaced, and startup says so. A file that cannot be read is named at WARN rather than refusing startup. `internal/config.EnvFileVar`; the `--env-file` flag sets the same thing and wins over it
- **`GITLAB_MCP_STDIO_MAX_LINE_BYTES`** (optional): Longest stdio message assembled, in bytes (default 4 MiB, matching the SDK's own HTTP body default so both transports refuse the same messages). A longer line is refused and answered rather than accumulated. An unset or blank value keeps the default in silence; a value that is unparseable or non-positive warns and keeps the default, because a mistyped number should not take the client down with the server, the exception register row `RQB-004` records (issue 957). `cmd/server.stdioMaxLineBytesEnv`, read by `stdioLimitsFromEnv`
- **`GITLAB_MCP_MAX_LISTEN_STREAMS`** (optional): Concurrent `subscriptions/listen` streams one credential may hold open (default 64; `0` removes the per-credential ceiling and nothing else: the same counter is what tells the pool a credential is holding a stream open, so removing the ceiling must not make a listening credential look idle). A second ceiling of 512 per process is deliberately not configurable: the per-credential one multiplies by however many tokens a caller holds, so only the process-wide one bounds the process. `MaxWatchers` does not cover this, since a listen asking only for list-changed notifications creates no watcher. A value that is not a whole number of 0 or more warns and keeps the default rather than refusing startup, the exception register row `HLD-001` records (issue 957). Both transports. Flag `--max-listen-streams`, which writes the variable. `cmd/server.maxListenStreamsEnv`
- **`GITLAB_MCP_TOOL_SURFACE`** (optional): Explicit tool catalog selector: `dynamic`, `meta`, or `individual`; `dynamic` when unset
- **`GITLAB_MCP_CAPABILITY_SURFACE`** (optional): Resource and prompt catalog selector: `full` or `minimal`; `minimal` keeps the surface-aware `gitlab://tools` manifest
- **`GITLAB_MCP_META_PARAM_SCHEMA`** (optional): Meta-tool input-schema strategy: `opaque` (default), `compact` (~9.3x), or `full` (~26.5x). Independent of `GITLAB_MCP_TOOL_SURFACE`. Per-action call shapes and input schemas are discoverable through `gitlab://tools` and `gitlab://tools/{id}` for every surface
- **`GITLAB_MCP_READ_ONLY`** (optional): Read-only mode: removes mutating operations per action; reads keep working on every surface (`false` default)
- **`GITLAB_MCP_SAFE_MODE`** (optional): Safe mode: intercepts mutating operations per action and returns a preview card naming the action and echoing its arguments (`toolutil.FormatSafeModePreviewMarkdown`, read back by `ParseSafeModePreview`); reads keep working (`false` default)
- **`GITLAB_MCP_TIER`** (optional): Licensing tier selector: `free`/`ce` (Free), `premium`, or `ultimate`. When set, the tier is used verbatim with no license check. When unset, the tier is detected in up to three steps, because no one of them answers for every deployment: `GET /license` carries the instance plan and is **admin-only on self-managed and unavailable to anyone on GitLab.com**, and `GET /namespaces` carries a plan per namespace the caller administers, which is the real subscription on GitLab.com and always `default` on self-managed, a subscription being a GitLab.com concept. Measured 2026-09-22 against a licensed EE 19.3.1 and against GitLab.com. `default` and an absent plan both mean the question went unanswered rather than that the answer is Free, which is what keeps a GitLab.com account on the `free` plan from being warned at every startup about a tier that is correct. Where no step answers the tier is `free`, and an enterprise build says so once at WARN naming this variable, while a CE build stays silent because Free is the truth there. Several paid namespaces resolve to the highest, on ADR-0018's asymmetry: a tier resolved too low silently removes tools, one resolved too high surfaces as GitLab's own refusal on the one call that needed it. The namespace listing is **paged**, stopping at the first `ultimate` (nothing later can raise the answer) and after `namespacePlanMaxPages` of `namespacePlanPageSize` either way, so an account administering more than a thousand namespaces whose only paid one sits past that bound resolves lower than it holds; reading one page alone was the first shape and resolved Free for exactly that caller. A page that fails after an earlier one answered keeps that answer. **On GitLab.com a third step asks the top-level groups the token is a member of** (issue 1224), unless the namespaces already answered `ultimate`: GitLab.com shows a namespace's plan only to a caller who may administer it, so a Reporter, Developer or Maintainer of a paid group resolved Free, while it serves a licensed feature to every member. The step is a paged GraphQL read, one query per page, `groups(allAvailable: false, topLevelOnly: true)` with each group's `licensedFeatureAvailability` of `EPICS` and of `SECURITY_DASHBOARD` (the roots of every group the caller is authorized in, a subgroup's included, which GitLab answers from the root's plan, trials and the open source program included), paged under `TierMembershipPageSize` and `TierMembershipMaxPages` (register row `AUT-003`), stopping at the first Ultimate, costing 22 of GitLab's 250 at a page of 100 (`internal/gitlab.MembershipTierQuery`, held by `internal/testutil`'s complexity test). The highest of the namespace and membership answers wins, a membership read that fails keeps the namespaces' answer, and a page GitLab answered in part keeps the groups it resolved and ends the walk (a fine-grained token, refused every group's `licensedFeatureAvailability`, is answered null nodes, so no group answers for it); a read that did not come back whole is logged at INFO naming this variable. `internal/gitlab.membershipTierApplies` keeps it to GitLab.com: a self-managed instance is licensed as a whole, which the first step reads. In HTTP mode use `--tier`; when omitted the tier is detected per token+URL pool entry when the entry is built and kept while it lives. Enterprise/Premium tools are gated when the resolved tier is Premium or Ultimate
- **`GITLAB_MCP_IGNORE_SCOPES`** (optional): Skip the scope filter and the `read_api` narrowing and register every tool the tier allows (`false` default). Flag `--ignore-scopes`. The token's scopes are still read, so a token carrying neither `read_api` nor `api` is still refused, on stdio with every catalog method answered `-40300` (issue 952), and a fine-grained token's grant still decides what it is shown
- **`GITLAB_MCP_EMBEDDED_RESOURCES`** (optional): Embed the canonical `gitlab://` resource URI in `get`-style tool results (`true` default). Flag `--embedded-resources`
- **`GITLAB_MCP_EXCLUDE_TOOLS`** (optional): Comma-separated tool names, group names or canonical action IDs removed from registration; they leave both the served surface and the withheld-action lists, since the operator asked for them not to exist. One rule on every surface, the standalone utilities included: `gitlab_interactive` removes the four guided flows and `interactive.issue_create` one of them, because `surfaces.ExcludedToolSpecs` asks the catalog's own matcher rather than keeping a copy (issue 911). An entry naming nothing is a WARN from `tools.ExcludeFromCatalog`, never a refusal, since one file is reused across tiers; it is written whenever a shared catalog is built, once per catalog key (tier, instance class and the scopes that narrow the catalog): at startup on stdio, and the first time each key is built in HTTP mode, where the tier is detected per pool entry unless pinned. It can therefore repeat, and an entry reported as naming nothing for one tier may still remove actions for another. The WARN also names the dynamic surface's own `gitlab_find_action` and `gitlab_execute_action`, although that surface removes them by name, because the function knows no surface. Flag `--exclude-tools`
- **`GITLAB_MCP_UPLOAD_MAX_FILE_SIZE`** (optional): Largest local file an upload or file-read tool accepts: a byte count or a `KB`/`MB`/`GB` suffix (`2GB` default, 1 TB upper bound). Flag `--upload-max-file-size`, which writes the variable. A value that does not parse, one that is not positive, one whose bytes do not fit in 64 bits and one above the bound refuse startup in both transports, naming the variable (register row `RQB-007`, issue 1170): `config.UploadMaxFileSizeFromEnv` is the one reader, which `config.Load` calls for stdio and the HTTP overlay (`loadOverlayUploadLimit`) for HTTP mode, and it reads the value trimmed, so a blank one is unset in both. HTTP mode used to read it outside the overlay, warning and using the default for a value it could not parse and the bound for one above it, stdio refused a blank value the overlay read as absent, and a count whose bytes overflowed used to wrap in both (`17179869185GB` was read as 1 GiB)
- **`GITLAB_MCP_MAX_HTTP_CLIENTS`** (optional): HTTP mode: maximum unique (token, GitLab URL) server entries kept in the pool (`100` default, upper bound 10000). Flag `--max-http-clients`. It bounds entries, not what an entry holds: the calls held open at once are bounded across the process by its descriptor limit (register row `HLD-011`, issue 951; 192 under a hard limit of 1024, 229120 under 524288), and on `--stateless=false` the sessions kept at half that (`HLD-010`; 96 under 1024); no flag moves either, and a call or an `initialize` past them is refused as busy
- **`GITLAB_MCP_SESSION_TIMEOUT`** (optional): HTTP mode: idle MCP session timeout, `--stateless=false` only (`30m` default, max 24h). Flag `--session-timeout`. A session no client deletes holds one of the process's stateful session slots, and the held-call slot reserved for its stream, until it expires, and with `0`, which the variable reads as off as the flag does (`END-005`, issue 958), until the pool evicts its credential (after `--pool-idle-timeout` without a request, or to make room at `--max-http-clients`), which startup warns about naming both spellings: the process keeps at most half as many sessions as it may hold calls across every credential (register row `HLD-010`, issue 951; 96 under a hard descriptor limit of 1024), not configurable, and refuses the next `initialize` in the gate as busy
- **`GITLAB_MCP_SESSION_REVALIDATE_INTERVAL`** (optional): Both transports: in HTTP mode the token re-validation interval of every pool entry, and on stdio the interval at which the process re-reads its fine-grained token's grant and the instance version, or asks again what its token is while that is unknown (`15m` default, `0` stops the periodic check in both, max 24h). Flag `--revalidate-interval` in HTTP mode. Stdio parsed the variable and re-read at the default whatever it said until issue 1171; `prepareStdioCatalog` now hands the configured interval to `refreshStdioAuthority`, which starts no timer for `0` (register row `ADM-009`, keyed on the process there)
- **`GITLAB_MCP_YOLO_MODE` / `AUTOPILOT`** (optional): Skip the confirmation of destructive actions when truthy (`1`, `true`, `yes`), on every surface: the meta and individual dispatchers ask nothing, and the dynamic surface's gate in `Registry.Execute` needs no `confirm` (issue 1166; read-only and safe mode still come first). `GITLAB_MCP_YOLO_MODE` decides whenever it is set; `AUTOPILOT` is the alias consulted only when it is not, so an inherited `AUTOPILOT=true` can be overridden. `internal/toolutil.IsYOLOMode`; flag `--yolo-mode`
- **`GITLAB_MCP_ALLOWED_UPLOAD_DIRS`** (optional): Extra directories a tool may READ a local file from (every `file_path` and `directory_path` input), separated by the OS path-list separator. The working directory (unless it is the filesystem root or the user's home directory, which are dropped as implicit roots) and the OS temp directory are always allowed; a path is canonicalized through symlinks before the check. A listed directory that does not resolve is skipped with a WARN and the rest of the list kept rather than refusing startup, since an entry that names nothing widens nothing, the exception register row `AUT-006` records for the three lists (issue 957). `internal/toolutil.UploadDirAllowlistEnv`
- **`GITLAB_MCP_ALLOWED_DOWNLOAD_DIRS`** (optional): Extra directories a tool may WRITE a downloaded file into (`output_path`), same syntax and same always-allowed roots. Checked twice, once before creating the parent directories and once after, so the second call resolves a parent that now exists. The bytes go to a temporary file beside the destination, renamed over it only once complete, so a failed or cancelled download leaves `output_path` as it was; `toolutil.WriteDownloadOutputFile` is the one way a download reaches a caller-named path, and does both checks itself. `internal/toolutil.DownloadDirAllowlistEnv`
- **`GITLAB_MCP_ALLOWED_IMPORT_DIRS`** (optional): Extra directories a project or group import archive may be read from, same syntax and same always-allowed roots. `internal/toolutil.ImportArchiveAllowlistEnv`
- **`GITLAB_MCP_ALLOW_PRIVATE_INSTANCES`** (optional): Permit a destination the operator did not choose to be a private, loopback, CGNAT, link-local, unique-local or unspecified address (`false` default). Two destinations are not the operator's choice: an instance a caller named in the `GITLAB-URL` header under `--allow-any-gitlab-url`, and a redirect hop that left the configured instance's own host, which is the exact host and not its subdomains: a subdomain is another name nobody chose, and is judged like any other hop (issue 1340), while the credential headers still follow one. An address `--gitlab-url` or `GITLAB_URL` named is never checked, whatever it resolves to, which is what keeps GitLab on `localhost`, on `10.x` or behind a VPN working with nothing set; and a redirect to a private address is allowed anyway when the instance the operator configured itself resolves private, which is the self-managed object store; an instance a caller named never qualifies, and needs `--allow-private-instances`. The cloud metadata addresses (`169.254.169.254`, `169.254.170.2`, `fd00:ec2::254`, `100.100.100.200`) are refused on every hop this process dials for every client, and behind a proxy on every hop whose URL spells one, and this does not permit them. Enforced at the dialer, after DNS resolution, so it covers the first request and every redirect alike; behind `HTTP_PROXY` or `HTTPS_PROXY` the dialer sees only the proxy, which gets tier A alone, and the destination is judged per request in `destinationTransport` as far as its URL spells it (NEG-004 of ADR-0022), a host that ends in a number read with the `inet_aton` grammar a libc proxy applies (`2852039166` is `169.254.169.254`) and one that ends in a number without being an address refused unless it is the configured instance (issue 1338). The IPv4 address an IPv6 one embeds behind the NAT64 prefixes `64:ff9b::/96` and `64:ff9b:1::/48` is judged by both tiers, under every layout of the local-use prefix the address fits (a reading of `0.0.0.0` aside), and `2002::/16` and `::/96` count as private; whether the configured instance is itself private counts a NAT64 address only when every reading is private, and neither tunnel prefix (NEG-007 of ADR-0022). A refusal is handed to client-go without the dial error it would retry. A value that does not parse reads as `false` rather than refusing startup, so a typo never turns the guard off, the exception register row `DST-003` records (issue 957). Flag `--allow-private-instances`; both transports. `internal/gitlab/destination.go`, [ADR-0022](adr/adr-0022-operator-named-destinations-are-exempt.md)
- **`GITLAB_MCP_AUTH_MODE`** (optional): HTTP mode auth: `legacy` (default) or `oauth` (RFC 9728 Bearer verification)
- **`GITLAB_MCP_PUBLIC_URL`** (optional): Externally reachable https origin; required with `GITLAB_MCP_AUTH_MODE=oauth` (RFC 9728 resource identifier; flag `--public-url`)
- **`GITLAB_MCP_TRUSTED_ORIGINS`** (optional): Comma-separated absolute origins allowed to make cross-origin browser requests; `*` accepts any origin and disables the protection; empty adds none, though a configured `GITLAB_MCP_PUBLIC_URL` origin is trusted regardless (flag `--trusted-origins`)
- **`GITLAB_MCP_ALLOW_PLAINTEXT_HTTP`** (optional): HTTP mode: the environment spelling of `--allow-plaintext-http` (`true` default, a Go boolean, anything else fails startup; `false` is the hardened mode, register row `ADM-015`). Read by the HTTP overlay only (`config.HTTPEnvOverlay.AllowPlaintextHTTP`), since stdio has no listener; it is the one listener setting with a variable, because a container that keeps the image's command cannot pass the flag without replacing that command
- **`GITLAB_MCP_OAUTH_CACHE_TTL`** (optional): OAuth token identity cache TTL (`15m` default, range 1m to 2h; a zero or a negative value refuses startup, as through the flag, since the verifier stamps the TTL into every token's expiration, issue 958). The cache holds at most 10000 identities whatever the TTL and, when full, drops an expired one or else the one used least recently (register row `ADM-005`, issue 950); at most 16 tokens it does not hold are verified at once across the process, a new one waits up to 5 s for a slot and is then refused `503` `-50300` with `Retry-After`, uncharged, in the words a verification with no verdict gets (`ADM-014`). Neither bound is configurable, and the ceiling bounds concurrency, not rate
- **`GITLAB_MCP_OAUTH_CLIENT_UID`** (optional): Comma-separated GitLab OAuth application uids whose tokens are admitted (flag `--oauth-client-uid`). Empty (default) admits any credential the instance accepts; setting it refuses personal access tokens, which belong to no application. RFC 8707 audience binding is unavailable (GitLab publishes no `resource_indicators_supported`), so this is the specification's "otherwise verify" alternative (ADR-0019)
- **`GITLAB_MCP_POOL_IDLE_TIMEOUT`** (optional): HTTP mode: reclaim a pooled per-token-and-URL credential entry after this long unused (`1h` default, `0` disables, max 24h). An entry with a live subscription is never idle by this measure, and size pressure prefers an entry that is not, so a quiet subscriber is only evicted when every entry is one
- **`GITLAB_MCP_ACTION_TIMEOUT`** (optional): Cancel an action still running after this long, in both transports (`65m` default, `0` disables, max 24h). Applied in the four `toolutil.WrapAction` functions every action is registered through, so it ends a handler whose client is still waiting; the transports already cancel a call whose client went away. The two void variants were skipping it until 2.8.0, which left deletes, cancels and retries unbounded. Above the longest wait any action offers (a pipeline wait caps itself at 3600 s). It reaches GitLab only through a request that carries the handler's context (`gl.WithContext(ctx)`), and so it bounds a file transfer too: an upload or download still running at the limit ends with its action. Flag `--action-timeout` in HTTP mode
- **`GITLAB_MCP_DRAIN_DELAY`** (optional): HTTP mode: after `SIGTERM`, keep the listener open and answer `/health` with `503 draining` (`Cache-Control: no-store`) for this long before closing it, so a balancer that polls `/health` removes the instance before the close (`0` default, max 5m). Set it to at least one probe interval. `/health` also carries `build` (closest release plus short commit, `.dirty` when the tree had changes; `cmd/server/health.go`) and `config_digest` (twelve hex over tool surface, capability surface, meta parameter schema, tier and whether it was pinned or is detected, scope detection, read-only, safe mode and excluded tools; a comparison fingerprint, not a secret) so the instances behind one balancer can be compared. Flag `--drain-delay`
- **`GITLAB_MCP_RATE_LIMIT_RPS`** (optional): Per-credential rate limit, in req/s, on every call that reaches GitLab (`tools/call`, `resources/read`, `resources/subscribe`, `subscriptions/listen`, `prompts/get`) (`0` = disabled). The bucket lives on the pool entry, so each token and URL pair is limited on its own, whatever server shape serves it. `tools/list` is charged too, on a bucket of its own refilled a tenth as fast, for the opposite reason to the rest: it reaches no GitLab, and instead spends the processor every tenant of the process is waiting for (about 3.2 MB marshalled per listing on the individual surface). Its burst is the configured one, undivided, so a fleet of clients sharing one credential can still all discover at once; the refill is what bounds a client listing in a loop. Keeping the buckets apart is what lets a drained tool-call bucket still answer a client's discovery. A listing is charged first to a bucket the whole process shares, counted in the tools a listing carries (3000 tools a second, 48000 in hand; register row `RTC-007`), because a credential's bucket multiplies by however many tokens a caller holds and the processor does not; it is not configurable, is off with the rest of the limiter at `0`, and refuses in the credential's own words, the log line alone naming it (`scope=process`). On stdio this variable is the only switch, since stdio ignores `--rate-limit-rps` and says so at startup (issue 1045), and its default of `0` is issue 959's position on MCP's "Rate limit tool invocations": met by default in HTTP mode, off by default on stdio, where one process serves one person (`test/e2e/stdio/rate_limit_test.go` holds both halves)
- **`GITLAB_MCP_RATE_LIMIT_BURST`** (optional): Token-bucket burst size when RPS > 0 (`40` default)
- **`GITLAB_MCP_AUTH_FAILURE_LIMIT`** (optional): Failed authentications one address, an IPv6 one by its `/64` (`cmd/server.budgetKey`), may produce inside the failure window before it is blocked (`10` default, max 100000). `0` turns the budget off, and that is the one value it must not be read literally on: the limiter blocks once a record reaches its limit, so a zero would block an address after a single failure, which is the harshest setting there is reached by typing the figure every other budget here reads as "none". `cmd/server.authFailureLimiter` returns nil instead, and every consulting site already tolerates that
- **`GITLAB_MCP_AUTH_FAILURE_WINDOW`** (optional): Window the failure budget counts in (`1m` default, max 24h), and the step the distinct-credential escalation is built from: one window, then ten, then sixty, reset after sixty of silence. Deriving the ladder rather than giving it four more settings is what lets a test set this to a second and watch the whole thing in seconds. `0` turns the failure budget off and nothing else: the escalation then steps by the default window, as the transport-source budget and the `/48` aggregate count in it (`cmd/server.windowOrDefault`, issue 958)
- **`GITLAB_MCP_AUTH_DISTINCT_TOKEN_LIMIT`** (optional): Distinct credentials one address, an IPv6 one by its `/64`, may have refused inside the distinct window before it is blocked, for longer each time (`50` default, max 100000, `0` disables). It asks a different question from the failure budget, and that is what makes it safe to escalate on: ten failures in a minute is a stuck client as much as an attack, while fifty _distinct_ invalid tokens is only an attack, since a person has one token and a fleet behind a NAT has one each. Credentials are held as truncated SHA-256 digests, never in the clear
- **`GITLAB_MCP_AUTH_DISTINCT_TOKEN_WINDOW`** (optional): Window the distinct-credential budget counts in (`10m` default, max 24h)
- **`GITLAB_MCP_DISCOVERY_RATE_LIMIT_RPS`** (optional): HTTP mode: refill, in requests a second, of the token bucket one client address draws on for the three documents served without a credential, the SEP-2127 server card at every path it is mounted at, the legacy enumerating card and, in oauth mode, the RFC 9728 metadata, prefix forms included (`20` default, max 1000; issue 1053, register row `RTC-008`). One bucket for the three, keyed as the authentication budgets key an address (`clientIP` with the trusted-proxy rules, then `budgetKey`, an IPv6 address by its `/64`). Every request to those paths draws on it, a revalidation answered `304` and a CORS preflight among them, since what is bounded is the request; `/health` and the MCP endpoint do not. A request its bucket cannot pay for is refused `429` with `Retry-After: 1` (`tenancy.DiscoveryRetryAfter`, fixed rather than read off the bucket) and the gate's JSON-RPC body, code `-42900`, charged to no budget. No bucket the whole process shares stands beside it, which issue 1053 decided and finding F-36 records, since one would let a flood from many addresses deny discovery to every caller; the table keeps at most 4096 addresses (`tenancy.DiscoveryTrackedAddresses`), a new one taking the place of the one used least recently, and is swept of refilled buckets on the authentication tables' five-minute interval. `0` here or in the burst turns it off, for a reverse proxy that limits these paths already. The default and its burst are sized from the measurement issue 1053's pull request took (`BenchmarkDiscoveryDocuments` in `cmd/server`, `make bench-fairness BOUND=discovery`). Flag `--discovery-rate-limit-rps`; `cmd/server/discovery_rate.go`
- **`GITLAB_MCP_DISCOVERY_RATE_LIMIT_BURST`** (optional): HTTP mode: requests that bucket holds at once (`200` default, max 10000, `0` turns it off). Flag `--discovery-rate-limit-burst`
- **`GITLAB_MCP_CLIENT_COMPAT`** (optional): Per-client response compatibility (`auto` default): Codex sessions get float `priority` in annotations rounded to 0/1; `off` disables. Choosing a response from `clientInfo` departs from MCP 2026-07-28's SHOULD NOT on purpose (issue 959, register row `IDN-013`): it only changes how one number is written, never who a caller is or what it may do, and it retires with row 17 of `docs/development/upstream-bugs.md`. The session's `clientInfo` decides whenever it has one, matched to Codex's own spellings (a `codex-mcp-client` name prefix or a title of exactly `Codex`, so an `openai-mcp` label carrying the word is not caught); a session with none, which is every call of a client on protocol 2025-11-25 or earlier over the default stateless HTTP transport, falls back to a `codex-mcp-client/` User-Agent prefix (issue 1043, recorded on `IDN-013`; `test/e2e/http` holds both and the negatives). Read from the process environment in both stdio and HTTP modes; the `--client-compat` flag writes the same variable. See `internal/clientcompat` and [client compatibility](https://docs.jmrp.io/gitlab-mcp-server/compatibility/)
- **`GITLAB_MCP_DESCRIPTION_SUBSTITUTIONS`** (optional): Rewrite listed catalog text for strict MCP gateway validators: comma-separated `old=new` pairs applied in order to every listed description and title (backslash escapes `\,` `\=` `\\`). Covers tools (all surfaces, schema-embedded descriptions included), prompts, resources, and resource templates; never names, URIs, `pattern`, `const`, enum values, or tool-call payloads. Malformed values refuse startup. Flag `--description-substitutions`; both modes. The served surface itself stays pure ASCII with no semicolons (`make check-gateway-chars`); verify a config with `go run ./cmd/audit_gateway_chars/ -apply -check`. See `internal/gatewaycompat` and [client compatibility](https://docs.jmrp.io/gitlab-mcp-server/compatibility/)
- **`GITLAB_MCP_TELEMETRY`** (optional): Export OpenTelemetry traces, metrics and logs over OTLP (`false` default). Off for privacy: telemetry goes to a collector the operator configures, never to the maintainer; the exporters' only default is their own `localhost`. Endpoint, credentials, sampling and batching all come from the standard `OTEL_EXPORTER_OTLP_*` variables the exporters read themselves. `OTEL_SDK_DISABLED=true` vetoes it regardless. Read by the OpenTelemetry boolean rule: only `true` or `false`, in any case, and anything else warns and reads as `false`; the flag is parsed by Go's flag package, which refuses what it cannot parse. Flag `--telemetry`. See [telemetry](https://docs.jmrp.io/gitlab-mcp-server/operations/telemetry/)
- **`GITLAB_MCP_TELEMETRY_IDENTITY`** (optional): How much telemetry records about who made a call: `none` (default, records nobody), `pseudonymous` (a per-process HMAC digest that correlates one caller's calls without naming them), or `full` (`user.id` and `user.name`). Identity never reaches a metric under any policy. While telemetry is on, a value it does not know refuses startup on either transport, naming the flag or the variable that held it (register row `IDN-009`, issue 957): `telemetry.Start` asks `cmd/server.validateTelemetryIdentity` through `Config.Check` once the switch is on and `OTEL_SDK_DISABLED` has not vetoed it, before anything is built, and with telemetry off nothing is exported under it and nothing is refused. Flag `--telemetry-identity`
- **`GITLAB_MCP_TELEMETRY_IDENTITY_KEY`** (optional): Secret the `pseudonymous` policy derives its pseudonymisation keys from (HKDF-SHA256, one key for callers and one for resource URIs). Empty (default) generates one per process, so a digest identifies a caller within one process and nowhere else. Set it when several replicas must agree, or when a distinct-user count has to survive a restart; it then never rotates here, because a key the operator supplied is theirs to rotate. Setting it makes the pseudonym a person pseudonym in EDPB terms, and the key is Article 4(5) "additional information": keep it away from wherever the telemetry lands, since GitLab user ids are small enough to enumerate against a known key. No flag on purpose: process arguments are readable through `/proc` by any local principal
- **`GITLAB_MCP_TELEMETRY_IDENTITY_ROTATION`** (optional): How long a **generated** pseudonymisation key lives, e.g. `24h`. Empty or `0` (default) keeps it for the life of the process; maximum 30 days. While telemetry is on and no key is set, a value that does not parse or lies outside that range refuses startup, by the same check as the policy and `telemetry.CheckKeyRotation`, the rule the keyring is built by. Ignored when `GITLAB_MCP_TELEMETRY_IDENTITY_KEY` is set, whatever it says, so it refuses nothing beside a key; a positive duration set beside the key is named at WARN while telemetry is on and the policy records callers. Off by default because replicas start at different moments and would rotate out of phase, churning a distinct-user count nobody asked to churn. Flag `--telemetry-identity-rotation`
- **`GITLAB_MCP_TELEMETRY_TOOL_NAME`** (optional): Whether `gen_ai.tool.name` and `gitlab_mcp.action` are metric dimensions, the two decided together because on individual each tool is one action and keeping either keeps every series (issue 1329): `auto` (default), `on` or `off`. `gitlab_mcp.domain` is kept under every value, and spans carry both whatever it says. Auto keeps them on the dynamic and meta surfaces and drops them on individual, where ~1099 tools would exhaust the SDK's 2000-series cardinality limit and collapse the long tail into one `otel.metric.overflow` bucket, first-come-wins under cumulative temporality. Implemented as a metric View, because filtering runs before the limit is counted. A value it does not know is logged and `auto` is used rather than refusing startup, an exception register row `IDN-014` records with its reason (issue 957). Flag `--telemetry-tool-name`
- **`GITLAB_MCP_LANGUAGE`** (optional): Language of the texts a client shows a person directly (elicitation questions, form field titles, progress messages), issue 1547: a BCP 47 tag read without regard to case, whose subtags after the language are dropped (`en-GB` is `en`); unset or blank is `en`. The message catalog (`internal/i18n`) ships English, the source, and Spanish, so the values are `en` and `es` (`es-ES`, `es-419` and `ES` are `es`), and under `es` a person is asked and told about progress in Spanish while every listing, result, refusal, log and the help stay English. A language without a catalog, or a value that is not a tag (`spanish`, `es_ES`), refuses startup in both transports, naming the variable and the two languages (`expected one of en, es`): `config.LanguageFromEnv` is the one reader, which `config.Load` calls for stdio and the HTTP overlay (`loadOverlayLanguage`) for HTTP mode, before the listener opens. It is on `prefixedNames` and not on `hadOldSpelling`, because the bare `LANGUAGE` is gettext's and a Linux desktop exports one (`es_ES:es`); the machine's locale (`LANG`, `LC_ALL`, `LC_MESSAGES`) is never read either. Per process, for every credential alike; `cmd/server.languageMiddleware` puts it on each request's context, and `serverShapeKey` carries it. No register row: it is presentation per deployment and decides nothing about who a caller is or what it may hold. Both transports. Flag `--language`, which writes the variable
- **`GITLAB_MCP_LOG_LEVEL`** (optional): Logging verbosity (`debug`, `info`, `warn`, `error`). Flag `--log-level`
- **`GITLAB_MCP_PPROF_ADDR`** (optional): Serve Go's profiling handlers (`net/http/pprof`) on this address, on an `http.Server` of their own that starts before the transport and stops with the process, so a CPU profile of startup can be taken. Loopback only (`127.0.0.1:port`, `[::1]:port`, `localhost:port`): anything else is refused at startup, because a heap profile is a copy of the process's memory and the handlers take no credential. Empty (default) serves nothing. Both transports; flag `--pprof-addr`. `cmd/server/pprof.go`; the benchmark's concurrency series starts the server with it
- **`MODELEVAL_MODELS`** (optional): `test/e2e/modeleval`: comma-separated `provider:model;key=value` specs a run asks. `fake:perfect` replays each case's own answer key through the whole pipe with no provider call, which is the rehearsal; folding a fake run publishes nothing and refuses every row by name
- **`MODELEVAL_SPEND`** (optional): `test/e2e/modeleval`: the consent a run asking a real provider needs (`yes`, `true`, `1`). Empty is no. A misspelled value is refused rather than read as no, because a run refused for a typo costs a moment and a run started by one costs money
- **`MODELEVAL_BUDGET_USD`** (optional): `test/e2e/modeleval`: the ceiling in US dollars a run stops at. `MODELEVAL_UNPRICED` lets a run start with a model the price table has no figure for, which otherwise refuses
- **`MODELEVAL_SURFACES`** (optional): `test/e2e/modeleval`: surfaces to measure (`dynamic,meta` by default). Individual is left out by cost, not by disinterest: its tools/list is 682,878 tokens at Ultimate, so it can only be put to a model on a deterministic slice, and `MODELEVAL_SLICE` (128) is that budget
- **`MODELEVAL_CASES`** (optional): `test/e2e/modeleval`: comma-separated case IDs; empty asks every case. This is how one corrected case is re-run and re-folded on its own
- **`MODELEVAL_MODE`, `MODELEVAL_TIER`, `MODELEVAL_META_PARAM_SCHEMA`, `MODELEVAL_REPEAT`, `MODELEVAL_PARALLEL`, `MODELEVAL_PROBE`** (optional): `test/e2e/modeleval`: the protective mode, the tier pin, the meta schema mode served, how many times each attempt runs, how many are in flight, and the consent the provider contract probe needs. Each counted setting has a ceiling, so a mistyped figure is a refusal rather than a bill
- **`GITLAB_MCP_TEST_INVENTORY_DIR`** (optional): `internal/testutil`: absolute directory the test transport records every request it sees into, one shard per test process, merged by `cmd/gen_request_inventory`. Empty (default) records nothing. A relative path is refused rather than resolved, because a test binary runs in its own package directory and would scatter a shard under each of 178 of them
- **`GITLAB_MCP_TEST_SNAPSHOT_PARITY`** (optional): Every unit test that compares a **committed, generated artifact** with what the tree generates now: `deferred` skips it with a message saying why, through the one reader, `internal/freshness`. Eight packages read it: `internal/tools` (the golden snapshots: `TestToolSnapshots_*` and the two `GoldenSnapshotParity` tests), `cmd/audit_tokens` (the token footprint targets), `cmd/gen_llms` (one subtest per committed llms file, and only those: the surface facts asserted beside them are not about a committed artifact and keep running), `cmd/audit_metrics` (`site/src/data/stats.json`), `cmd/gen_lhm_manifest` (`lhm.plugin.json`), `cmd/gen_model_corpus` (the corpus breadth ledger), and `cmd/audit_1to1/internal/grants` and `cmd/audit_1to1/internal/required` (the R-GRANT and R-INPUT requiredness runs over the tree, which read committed records); `internal/freshness/doc.go` lists them and a test holds that list to the callers. CI sets it from `FRESHNESS` in `ci.yml`, in the coverage job and the cross-platform matrix alike, which is `deferred` on every layer of a GitHub stack below its top (told by `github.event.pull_request.stack.position`, since a stacked layer is tested as the stack merged into `main` and `github.base_ref` is `main` for all of them) and on a pull request outside a stack whose base is not `main`, and `checked` at the top of a stack, on a pull request to `main` and on a push to `main`: every freshness gate (stats, llms, footprint, testing reference, manifests, request inventory, snapshots) compares a committed artifact with what the tree generates now, and a stack refreshes those once at its top. Empty (default) compares, which is also what the race workflow and a developer's machine do. A test that pins the value to `checked` must therefore compare no committed artifact, or it fails on exactly the layer the deferral exempts

None of the three `GITLAB_MCP_ALLOWED_*_DIRS` allow-lists applies in HTTP mode: a server reached over HTTP refuses every caller-supplied local path, since the caller has no files on the machine the server runs on and `content_base64` is the remote form. The transport is inferred from the process arguments in `internal/toolutil/file_utils.go`, so a deployment that never heard of this policy still gets the right answer.

## HTTP mode flags

In **HTTP mode**, configuration is resolved in three layers: an explicitly passed flag, then the environment variable with the same meaning (`internal/config/http_overlay.go` reads only the variables actually present, validated with the same parsers and bounds as stdio for the settings both transports have, and with the bound its flag is held to for the ones only HTTP mode has), then the built-in default. A variable exported without its flag is therefore honored, and an invalid value fails startup rather than falling back silently. Every flag in the list below but the four telemetry ones, which both transports read, lands in `httpConfig`, which a stdio run never reads, so a stdio run given one names it at startup and ignores it (`cmd/server/http_only_flags.go`, issue 1045): one WARN line listing each with the variable stdio reads instead (`--max-request-body-bytes` names `GITLAB_MCP_STDIO_MAX_LINE_BYTES`, the line ceiling that bounds the same message). Under `--transport=auto`, whose command line serves either transport, a flag stdio has no setting for at all (the image's own `--http-addr`, the pool, the authentication gate) is named at INFO instead, and a setting stdio has a variable for stays at WARN. The condition for refusing rather than naming is what ignoring the value would cost, the rule `config.RetiredEnvUses` applies to the retired names, and two kinds refuse the start in either case: `--read-only`, `--safe-mode` or `--exclude-tools` asking to withhold something (register row `AUT-004`'s three), since ignoring one serves it, and a `--gitlab-url` naming no instance a stdio run connects to, since stdio sends `GITLAB_TOKEN` to the one `GITLAB_URL` names, `https://gitlab.com` when it is unset. A flag is refused even when its variable already asks for the same thing, as a retired name is beside its replacement. `httpOnlyFlags` is held to the registrations into `httpConfig` by a test that reads the source, each variable it names to what stdio reads and, through the HTTP environment overlay, to the field its flag writes, and `test/e2e/stdio/http_only_flags_test.go` holds the lines and both refusals against the binary, the second with an instance counting that no request reached it:

- **`--gitlab-url`** (default _(none)_): GitLab instance URL. **Required in HTTP mode** unless `--allow-any-gitlab-url` is passed: a deployment that names no instance makes requests to whatever host a caller puts in `GITLAB-URL`, with whatever token that caller supplied. Repeatable/comma-separated: all are published in RFC 9728 `authorization_servers`, and `GITLAB-URL` then selects among them. With several published the header is **required** in both auth modes (400 without it), and a value outside the list is refused rather than ignored (400 from the legacy gate, 403 from the oauth bearer guard). The refusal names the published instances only in oauth mode, where RFC 9728 metadata already serves that same set unauthenticated; legacy mode publishes no metadata and rejects before the credential is judged, so it says to ask the operator rather than let any non-empty token enumerate the operator's hostnames
- **`--allow-any-gitlab-url`** (default `false`): Start with no instance published, letting `GITLAB-URL` name any host. For a single-user local deployment where the operator is the caller, and refused anywhere else: `--http-addr` must bind a loopback address or a unix socket, since on a listener anyone else can reach the hatch is the request forgery of GHSA-fcj2-hj27-hj26 opted into. It warns at startup even on loopback. `cmd/server.listenerIsHostLocal`
- **`--skip-tls-verify`** (default `false`): Skip TLS verification for self-signed certs
- **`--tool-surface`** (default _(empty)_): Explicit tool catalog selector: `meta`, `individual`, or `dynamic`; empty serves the default dynamic surface
- **`--capability-surface`** (default `full`): Resource and prompt catalog selector: `full` or `minimal`
- **`--meta-param-schema`** (default `opaque`): Meta-tool input-schema mode: `opaque`, `compact` or `full` (same setting as `GITLAB_MCP_META_PARAM_SCHEMA`)
- **`--tier`** (default _(empty)_): Force licensing tier: `free`, `ce`, `premium`, or `ultimate`. When set, used verbatim with no license check; when omitted, the tier is detected per token+URL pool entry by the same steps `GITLAB_MCP_TIER` describes, the instance license, then the namespace plans, then on GitLab.com the top-level groups the token is a member of, falling back to `free` with a warning on an enterprise build
- **`--read-only`** (default `false`): Read-only mode: removes mutating operations per action; reads keep working
- **`--safe-mode`** (default `false`): Safe mode: intercepts mutating operations per action, returns preview
- **`--embedded-resources`** (default `true`): Embed canonical MCP resource URIs in `get`-style tool results
- **`--exclude-tools`** (default _(empty)_): Comma-separated tool names, group names or canonical action IDs to exclude, on every surface
- **`--ignore-scopes`** (default `false`): Skip the scope filter and the `read_api` narrowing and register every tool the tier allows; the token's scopes are still read, so a token carrying neither `read_api` nor `api` is still refused (issue 952), and a fine-grained token's grant still decides what it is shown
- **`--max-http-clients`** (default `100`): Maximum unique (token, GitLab URL) server entries kept in the pool; bounds pooled entries, not sessions or the calls they hold, which the process bounds on its own by its descriptor limit (`HLD-011`: an eighth spare, one descriptor per listen stream at its 512, two per held call; 192 held calls under a hard limit of 1024; not configurable) and, on `--stateless=false`, at half that for sessions (`HLD-010`, 96). Positive and at most 10000, checked by `validateHTTPPoolAndRateBounds` in `cmd/server/main.go` along with the rate-limit ceilings: HTTP mode never runs `(*config.Config).validate`, so those documented bounds went unenforced there until 2.8.0 and a non-positive value fell back to the pool's own default of 100 without saying so
- **`--session-timeout`** (default `30m`): Idle MCP session timeout; applies to `--stateless=false` only, since under the default stateless transport each POST's session ends with its response. A session nobody deletes holds one of the process's session slots (`HLD-010`, 96 under a hard descriptor limit of 1024) until it expires, and with `0` until the pool evicts its credential, which startup warns about. Upper bound 24h, and a negative value refuses startup in `validateHTTPDurationConfig`, as the variable does, where it used to be read as off without that warning (issue 1171)
- **`--http-idle-timeout`** (default `0` (disabled)): HTTP server idle connection timeout; `0` (default) disables idle closure so `--session-timeout` is the effective lifetime; set a positive duration to recycle idle connections sooner
- **`--stateless`** (default `true`): Sessionless streamable HTTP (SEP-2567 / protocol 2026-07-28; default): no `Mcp-Session-Id` tracking, every POST is self-contained, GET/DELETE return `405`; synchronous server-initiated requests are unavailable, but protocol 2026-07-28 clients keep elicitation through MRTR. Use `--stateless=false` for legacy stateful sessions. Stateful sessions are capped across the process at half the held-call ceiling (`HLD-010`), and each session reserves a held-call slot (`HLD-011`) for its standalone `GET` stream when it opens, so a session the process keeps is never refused its stream; a POST on protocol 2026-07-28 or later takes no slot, since the stateful transport answers it with the revisions it serves
- **`--json-response`** (default `false`): Return `application/json` response bodies instead of `text/event-stream` (SSE)
- **`--max-request-body-bytes`** (default `0`): Maximum streamable HTTP request body size in bytes; `0` uses the SDK default (4 MiB)
- **`--http-addr`** (default `:8080`): Listen address. `host:port` binds TCP; a value containing a path separator binds a unix socket instead. Host-local: a same-host proxy connects through it and the TCP hop between them disappears rather than being encrypted; remote clients still arrive via that proxy
- **`--http-socket-mode`** (default `0660`): Octal permission mode for a unix socket named by `--http-addr`
- **`--tls-cert` / `--tls-key`** (default _(none)_): PEM certificate and key; serves HTTPS on the listener itself, for a proxy that does not share the machine. Both or neither, TLS 1.2 floor. Served through `tls.Config.GetCertificate` (`cmd/server/tls_reload.go`), which stats both files on each handshake and re-reads the pair when either changed, so a rotation is two file writes and no restart; a half-written or unreadable pair keeps the previous certificate and warns once. The first load is still strict and stops startup. `ServeTLS` is deliberately given no filenames, since `net/http` would replace the callback's certificate with one startup load of the named files
- **`--allow-plaintext-http`** (default `true`): What startup does with a TCP listener off loopback that serves plain HTTP; falls back to `GITLAB_MCP_ALLOW_PLAINTEXT_HTTP`, and the flag wins over the variable. It is a three-valued setting behind a boolean flag (`cmd/server.plaintextHTTP`), since a value the operator gave is not the default: unset, such a listener is served and `plaintextListenerWarning` is written at `WARN`, naming the remedies and the hardened mode; `true`, the operator's statement that something in front of the listener encrypts the hop, such as a proxy terminating TLS, serves it and writes `plaintextListenerAllowed` at `INFO`; `false` is the hardened mode, which refuses to start it, with an error naming the address and the ways to serve it (register row `ADM-015`). `cmd/server.checkPlaintextListener` decides in `runHTTP` after the TLS pair is validated and before the bind. A listener is off loopback when `listenerIsHostLocal` does not call it host-local: a wildcard bind, the default `:8080` and the image's `0.0.0.0:8080` included, a routable address, a name resolving to anything but loopback. Loopback, a unix socket and TLS write nothing and start in every mode. Plain HTTP stays served by default, as the maintainer decided on 2026-10-27 after reading [Refusing Plain HTTP off Loopback](plaintext-http-refusal-analysis.md); `test/e2e/http/listener_test.go` holds both lines and the refusal to the real binary
- **`--auth-mode`** (default `legacy`): Authentication mode: `legacy` or `oauth` (RFC 9728 Bearer verification)
- **`--public-url`** (default _(empty)_): Externally reachable https origin; required with `--auth-mode=oauth` (RFC 9728 resource identifier and metadata-URL derivation)
- **`--resource-documentation`** (default _(empty)_): https URL published as RFC 9728 `resource_documentation`; point it at a page describing your own OAuth application. Empty publishes this project's OAuth application page, `https://docs.jmrp.io/gitlab-mcp-server/operations/oauth-app/`
- **`--resource-policy-uri`** (default _(empty)_): https URL published as RFC 9728 `resource_policy_uri`; your own page on what this deployment does with the data reached through it. Empty omits the field, which is the right default: a link to a page that does not exist would land on a consent screen
- **`--resource-tos-uri`** (default _(empty)_): https URL published as RFC 9728 `resource_tos_uri`; your own terms of service. Empty omits the field
- **`--oauth-cache-ttl`** (default `15m`): OAuth token identity cache TTL (range 1m to 2h, checked in oauth mode; a zero or a negative value refuses startup in either authentication mode, as the variable does, where oauth mode used to start at the default and legacy mode left it unread, issue 958); the cache holds at most 10000 identities, an expired one or else the least recently used dropped first, and verification runs at most 16 at a time (`ADM-005`, `ADM-014`)
- **`--oauth-client-uid`** (default _(empty)_): Comma-separated GitLab OAuth application uids whose tokens are admitted; empty admits any credential the instance accepts
- **`--pool-idle-timeout`** (default `1h`): Reclaim a pooled per-token-and-URL credential entry after this long unused; `0` keeps entries until the pool size bound evicts them (upper bound: 24h), and a negative value refuses startup in `validateHTTPDurationConfig`, as the variable does (`POL-004`, issue 1171). An entry with a live subscription is never idle by this measure
- **`--action-timeout`** (default `65m`): Cancel an action still running after this long; `0` disables it (upper bound: 24h). Falls back to `GITLAB_MCP_ACTION_TIMEOUT`
- **`--drain-delay`** (default `0`): After `SIGTERM`, keep the listener open and answer `/health` with `503 draining` for this long before closing it, so a balancer that polls `/health` removes the instance before the close (upper bound: 5m); `0` closes at once. Falls back to `GITLAB_MCP_DRAIN_DELAY`
- **`--revalidate-interval`** (default `15m`): Token re-validation interval; `0` stops the periodic check, but an entry whose credential is older than 1h is still rebuilt, which re-runs the probe. Upper bound 24h, and a negative value refuses startup in `validateHTTPDurationConfig`, as the variable does (`ADM-009`, issue 1171). A stdio run given the flag names `GITLAB_MCP_SESSION_REVALIDATE_INTERVAL`, which stdio reads
- **`--trusted-proxies`** (default _(empty)_): Comma-separated addresses or CIDR ranges of the reverse proxies whose `--trusted-proxy-header` is believed (e.g. `127.0.0.1,10.0.0.0/8`). From any other peer the header is ignored and the peer itself is charged, so a caller who reaches the listener directly cannot choose the address its failures count against. For `X-Forwarded-For` the value is read from the right, skipping hops that are themselves listed, so the first hop nobody in the list vouches for is the client; a hop that is not an address charges the peer. A header split over several field lines is one list, the lines joined in order (RFC 9110 section 5.3), since HAProxy's `option forwardfor` appends a line of its own after the client's rather than extending it and reading the first line alone charged the address the client wrote (issue 1287). Required with `--trusted-proxy-header`, and refused without it. The entry `unix` trusts the peer of a connection accepted on a unix socket, which has no address and is otherwise the one key `unix` every caller on the socket shares; it trusts no address (issue 954). Two pairings with `--http-addr` refuse startup in `validateTrustedProxyListener`, since each trusts nobody: a socket listener whose list names addresses and no `unix` (it used to start with the header inert) and `unix` on a TCP listener. The address read here is keyed by `budgetKey` (a whole IPv4 address, an IPv6 address's fixed `/64`) and the `/48` aggregate by `networkKey`, both in `cmd/server/client_ip.go`, register rows `IDN-004`, `IDN-005` and `AUB-006`
- **`--trusted-proxy-header`** (default _(empty)_): HTTP header with real client IP for rate limiting behind proxies (e.g. `CF-Connecting-IP`, `X-Forwarded-For`); believed only on a connection from an address in `--trusted-proxies`, or from the socket's peer when it names `unix` (`trustedProxies.trustsPeer`), which it requires
- **`--rate-limit-rps`** (default `10`): Per-credential rate limit, in req/s, on every call that reaches GitLab (`tools/call`, `resources/read`, `resources/subscribe`, `subscriptions/listen`, `prompts/get`) (`0` disables it), plus `tools/list` on a separate bucket refilled a tenth as fast, with the same burst, charged because it spends the shared processor rather than because it reaches GitLab. The bucket lives on the pool entry, not on the shared server, so each token and URL pair is limited on its own. A listing is also charged, first, to one bucket the whole process shares, in tools listed (3000 a second, 48000 in hand, not configurable, `RTC-007`), which is what bounds the processor however many credentials list, and which `0` turns off with the rest. On by default in HTTP mode; the `GITLAB_MCP_RATE_LIMIT_RPS` env var used by stdio still defaults to `0`
- **`--rate-limit-burst`** (default `40`): Token-bucket burst size when --rate-limit-rps > 0
- **`--auth-failure-limit`** (default `10`): Failed authentications one address, an IPv6 one by its `/64`, may produce inside `--auth-failure-window` before it is blocked (`0` disables the budget rather than blocking on the first failure). Beside it and set by no flag, ten `/64`s of one IPv6 `/48` that each had a credential refused inside `--auth-distinct-token-window` block the `/48` on the distinct-credential ladder (`AUB-006`, `tenancy.AuthNetworkFailingPrefixes`); a window of zero there gives it the default window rather than switching it off
- **`--auth-failure-window`** (default `1m`): Window the failure budget counts in, and the step the distinct-credential escalation is built from; `0` turns the failure budget off alone, and the escalation steps by the default window (issue 958). A 429 announces in `Retry-After` the **longest** block actually holding the request rather than this window, since one failure can raise the minute-long lockout and an hour-long escalated block together and announcing the shorter one would tell a client to come back while it is still refused (`longestAuthBlock` in `cmd/server/auth_gate.go`)
- **`--auth-distinct-token-limit`** (default `50`): Distinct credentials one address, an IPv6 one by its `/64`, may have refused inside `--auth-distinct-token-window` before it is blocked, for longer each time (`0` disables). The admitted-credential exemption applies here too: a credential the pool already holds is still served from a blocked address
- **`--auth-distinct-token-window`** (default `10m`): Window the distinct-credential budget counts in
- **`--discovery-rate-limit-rps`** (default `20`): Requests a second one client address, an IPv6 one by its `/64`, may make for the documents served without a credential: the SEP-2127 card, the legacy enumerating card and the RFC 9728 metadata, one bucket for the three (`RTC-008`; see `GITLAB_MCP_DISCOVERY_RATE_LIMIT_RPS` above). At most 1000, and a negative value or one that is not a number refuses startup in `validateDiscoveryRateBounds`; `0` turns it off
- **`--discovery-rate-limit-burst`** (default `200`): Requests that bucket holds at once, at most 10000; `0` turns it off
- **`--telemetry`** (default `false`): Export OpenTelemetry traces, metrics and logs over OTLP. Applies to both transports. Endpoint and credentials come from the standard `OTEL_EXPORTER_OTLP_*` environment
- **`--telemetry-identity`** (default `none`): What telemetry records about the caller: `none`, `pseudonymous` or `full`; while telemetry is on, a value it does not know refuses startup, naming the flag
- **`--telemetry-tool-name`** (default `auto`): Whether `gen_ai.tool.name` and `gitlab_mcp.action` are metric dimensions, the two together: `auto`, `on` or `off`; `gitlab_mcp.domain` is kept either way
- **`--telemetry-identity-rotation`** (default _(empty)_): How long a generated pseudonymisation key lives, e.g. `24h`; ignored when a key is configured, and otherwise, while telemetry is on, a value that does not parse or lies outside 0 to 30 days refuses startup, naming the flag

## General flags (both stdio and HTTP modes)

- **`--http`** (default `false`): Serve HTTP instead of stdio
- **`--transport`** (default _(empty)_): `stdio`, `http` or `auto`; empty defers to `--http`. `auto` serves HTTP only when stdin is `/dev/null` (a container started without `-i`) and stdio for the pipe every MCP client provides. `cmd/server/transport.go`
- **`--env-file`** (default _(empty)_): Dotenv file to load besides `~/.gitlab-mcp-server.env`; the same setting as `GITLAB_MCP_ENV_FILE`, and wins over it
- **`--tool-search`** (default _(empty)_): Search the canonical action catalog by ID, tool name, alias, tag or description and exit. It searches the **catalog**, not a server's registered tools, because the default dynamic surface registers two and every other query used to answer "No tools found"; the actions found are therefore the same on every surface, and the surface decides only how each row names the call (individual tool, meta group tool plus `action=`, or the canonical ID `gitlab_execute_action` takes). On meta a standalone utility, `gitlab_discover_project` or a `gitlab_interactive_*` flow, is its own tool and is named with no `action=`, and `TestToolSearchCallForm_MetaNamesOnlyWhatTheMetaSurfaceServes` holds every meta row to the meta `tools/list` and its action enums (issue 1331). Surface and tier come from `--tool-surface` and `--tier` when passed and otherwise from `GITLAB_MCP_TOOL_SURFACE` and `GITLAB_MCP_TIER`, so a stdio deployment searches what it serves. No credentials needed
- **`--version`** (default `false`): Print version and exit
- **`--help` / `-h`** (default `false`): Curated help with flags, env vars and examples (both spellings give the same output)
- **`--allow-private-instances`** (default _(empty)_, which leaves the variable to decide, `false` when unset): `true` permits a destination the operator did not choose to be a private, loopback or CGNAT address: an instance a caller named in `GITLAB-URL` under `--allow-any-gitlab-url`, or a redirect hop that left the configured instance. Cloud metadata addresses stay refused whatever it says, and an address `--gitlab-url` named is never checked. Writes `GITLAB_MCP_ALLOW_PRIVATE_INSTANCES`; both transports. [ADR-0022](adr/adr-0022-operator-named-destinations-are-exempt.md)
- **`--log-level`, `--client-compat`, `--upload-max-file-size`, `--yolo-mode`, `--description-substitutions`, `--pprof-addr`, `--max-listen-streams`, `--language`** (default _(empty)_, which leaves each variable to decide, with its own default): Flags for settings whose only home used to be an environment variable; `--max-listen-streams` is the flag issue 957 gave the listen ceiling, which `INV-017` asks of a limit in HTTP mode, and `--language` was declared with its variable. Each writes its variable (the `GITLAB_MCP_` spelling, or `GITLAB_MCP_YOLO_MODE`) before anything reads it, so there stays one reader per setting and an explicitly passed flag beats the environment. `GITLAB_TOKEN` deliberately has no flag: a token on a command line is readable through `ps` and shell history. `cmd/server/env_flags.go`
- **`--shutdown`** (default `false`): Terminate all running instances of this binary and exit. Used by external updaters (pe-agnostic-store) before replacing the binary on disk.
- **`--probe`** (default `false`): Ask the running instance's `/health` and exit 0 when it answers 200; the image's `HEALTHCHECK`. With no argument it finds the other instances of this binary (the same lookup as `--shutdown`), reads `--http-addr`, `--tls-cert`, `--transport` and `--http` off their command lines, and probes where they listen: another port, a unix socket, or HTTPS pinned to the certificate `--tls-cert` names (a given `https://` target takes the pin from the probe's own `--tls-cert`, and the standard verification without one). A relative socket path or `--tls-cert` is resolved against the instance's own working directory (`peerWorkingDir`, gopsutil's `Cwd`, which on Linux is `/proc/<pid>/cwd`), and one that cannot be read is named as the failure rather than replaced by the probe's own (issue 1332). `--transport auto` is settled the way the server settled it, by reading the instance's file descriptor 0 from procfs; an instance serving stdio has nothing to probe and is reported healthy while it runs, but only when no HTTP instance was found: every HTTP listener is asked first, and one that does not answer is not excused by a stdio process beside it. A URL, `unix:<path>` or `host:port` after the flag probes that instead. Exit 1 when nothing answered, 2 for a target that does not parse. `cmd/server/probe.go`
