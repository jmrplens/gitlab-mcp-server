## GitLab edition compatibility

GitLab MCP Server works with both Community Edition (CE) and Enterprise Edition (EE). The Enterprise/Premium catalog unlocks {stats.meta.self_managed_enterprise - stats.meta.base} additional enterprise-only domains, registered as extra meta-tools with `TOOL_SURFACE=meta`, extra `gitlab_*` tools with `TOOL_SURFACE=individual`, and extra catalog actions on the default dynamic surface: set `GITLAB_TIER=premium` (or `GITLAB_TIER=ultimate`) in stdio mode, use `--tier=premium`/`--tier=ultimate` in HTTP mode, or rely on auto-detection from `GET /license` (fallback `free`). The deprecated `GITLAB_ENTERPRISE=true` environment variable is still honored when `GITLAB_TIER` is unset (it maps to `ultimate`) and logs a warning. There is no `--enterprise` flag in HTTP mode — passing one aborts startup; use `--tier`.

| Feature                                                                    | Community (CE) | Enterprise (EE) |
| -------------------------------------------------------------------------- | :------------: | :-------------: |
| Projects, Issues, MRs, Pipelines, CI/CD                                    |       ✅        |        ✅        |
| Wikis, Labels, Milestones, Releases                                        |       ✅        |        ✅        |
| Users, Groups, Members, Search                                             |       ✅        |        ✅        |
| Deployments, Environments, Packages                                        |       ✅        |        ✅        |
| {stats.meta.base} base domains (meta-tools with `TOOL_SURFACE=meta`)       |       ✅        |        ✅        |
| {stats.resources} resources, {stats.prompts} prompts                       |       ✅        |        ✅        |
| Merge Trains                                                               |       ❌        |        ✅        |
| DORA Metrics                                                               |       ❌        |        ✅        |
| Vulnerability Management                                                   |       ❌        |        ✅        |
| Audit Events                                                               |       ❌        |        ✅        |
| Compliance Policies                                                        |       ❌        |        ✅        |
| +{stats.meta.self_managed_enterprise - stats.meta.base} enterprise domains |       ❌        |        ✅        |

To enable enterprise features in stdio mode, set `GITLAB_TIER=premium` or `GITLAB_TIER=ultimate`. In HTTP mode, set `--tier=premium`/`--tier=ultimate` to force the Enterprise/Premium catalog, or omit it to let the server auto-detect CE/EE per token+URL entry when GitLab reports edition. The deprecated `GITLAB_ENTERPRISE=true` variable still works when `GITLAB_TIER` is unset; there is no `--enterprise` flag — use `--tier`.

## Platform support

Pre-built binaries are available for all major platforms:

| OS      | Architecture          | Binary                                |
| ------- | --------------------- | ------------------------------------- |
| Linux   | amd64                 | `gitlab-mcp-server-linux-amd64`       |
| Linux   | arm64                 | `gitlab-mcp-server-linux-arm64`       |
| macOS   | amd64 (Intel)         | `gitlab-mcp-server-darwin-amd64`      |
| macOS   | arm64 (Apple Silicon) | `gitlab-mcp-server-darwin-arm64`      |
| Windows | amd64                 | `gitlab-mcp-server-windows-amd64.exe` |
| Windows | arm64                 | `gitlab-mcp-server-windows-arm64.exe` |

The Linux binaries are dynamically linked position-independent executables and require glibc. On musl systems (Alpine), run the container image `ghcr.io/jmrplens/gitlab-mcp-server` instead — it is built against musl inside the image. The npm linux packages declare `libc: glibc` for the same reason and are skipped on musl by design.

### Per-client compatibility profiles

Most clients ignore MCP fields they do not understand, so the server ships its full surface to everyone. The one exception is handled automatically: the Codex builds bundled with ChatGPT.app reject results whose content annotations carry a fractional `priority` value, so when a session identifies itself as Codex the server rounds those priorities to the nearest spec-legal integer. Everything else — audience annotations, structured content, output schemas, icons — is delivered unchanged, and no other client is affected. Set `CLIENT_COMPAT=off` to disable the rewriting.

For Codex, add the server to `~/.codex/config.toml` with tool pre-approval — without it, Codex asks for confirmation on every non-read-only tool, and non-interactive `codex exec` runs cancel those calls:

```toml title="~/.codex/config.toml"
[mcp_servers.gitlab]
command = "/path/to/gitlab-mcp-server"
args = ["stdio"]
default_tools_approval_mode = "approve"

[mcp_servers.gitlab.env]
GITLAB_URL = "https://gitlab.example.com"
GITLAB_TOKEN = "glpat-xxxxxxxxxxxxxxxxxxxx"
```

Keep the default `dynamic` tool surface for clients with tool-count limits (Cursor caps servers at 40 tools, Windsurf at 100, OpenAI-backed clients at 128 per request) and keep `META_PARAM_SCHEMA` at its `opaque` default for Codex, which silently trims tool schemas larger than ~5 KB.

### MCP gateway validators

An MCP gateway validates a server's catalog before admitting it, under rules its operator chooses — one production gateway (IBM [mcp-context-forge](https://github.com/IBM/mcp-context-forge) before 0.7.0) rejected any tool description containing a semicolon. The server keeps everything it lists pure ASCII with no semicolons, on every surface (a character class holds against the next rule better than a codepoint list), and a substitution knob lets a deployment meet a new gateway rule without waiting for a release:

```bash
# Rewrite listed descriptions and titles: comma-separated old=new pairs,
# applied in order (backslash escapes \, \= \\)
GITLAB_MCP_DESCRIPTION_SUBSTITUTIONS=';=.'
```

The rewrite covers tool, prompt, resource, and resource-template descriptions and titles, including descriptions embedded in tool schemas. Names, URIs, schema constraints (`pattern`, `const`, enum values, defaults) and tool-call results are never touched, and a malformed value refuses to start the server instead of serving an unrewritten catalog. If your gateway is mcp-context-forge, upgrading to 0.7.0 or later also resolves the semicolon rejection on the gateway side ([issue 3770](https://github.com/IBM/mcp-context-forge/issues/3770)).

## MCP protocol features

GitLab MCP Server implements the full set of MCP capabilities beyond tools — resources, prompts, completions, elicitation, progress notifications, and resource subscriptions — so compatible clients get contextual data, prompt templates, argument autocompletion, and live change notifications in addition to tool calls.

| Capability    |                                                                                                                      Supported                                                                                                                      |
| ------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------: |
| Tools         | ✅ (up to {stats.tools.ultimate_self_managed} self-managed Enterprise / {stats.tools.gitlab_com} GitLab.com + Orbit individual / {stats.meta.base} base, {stats.meta.self_managed_enterprise} self-managed, {stats.meta.gitlab_com} GitLab.com meta) |
| Resources     |                                                                                                                ✅ ({stats.resources})                                                                                                                |
| Prompts       |                                                                                                                 ✅ ({stats.prompts})                                                                                                                 |
| Completions   |                                                                                                       ✅ ({stats.completions} argument types)                                                                                                        |
| Elicitation   |                                                                                                                          ✅                                                                                                                          |
| Progress      |                                                                                                                          ✅                                                                                                                          |
| Subscriptions |                                                                             ✅ (26 resource kinds, [honored by polling](/gitlab-mcp-server/capabilities/subscriptions/))                                                                             |

The {stats.tools.ultimate_self_managed} self-managed and {stats.tools.gitlab_com} GitLab.com figures are the expanded set of distinct tool instances. The {stats.meta.base} base, {stats.meta.self_managed_enterprise} self-managed, and {stats.meta.gitlab_com} GitLab.com counts are meta-tool catalog sizes whose actions expand to that larger individual tool surface.
