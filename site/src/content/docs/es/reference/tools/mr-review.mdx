Lo que hace una revisión con un merge request: leer sus cambios, sus versiones del diff y sus diffs en bruto; leer y escribir sus notas; abrir, responder y resolver discusiones en hilo, en línea sobre una línea del diff o generales; y encolar notas en borrador que siguen siendo privadas hasta que se publican, una a una o todas juntas como una sola revisión.

Aprobar, fusionar y el resto del ciclo de vida del merge request están en [Merge requests](/gitlab-mcp-server/reference/tools/merge-request/), igual que los emoji de reacción en sus notas.

## Preguntas de ejemplo

- "¿Qué ha cambiado en el merge request !15?"
- "Comenta la línea 42 de src/app.go en el merge request !15"
- "Resuelve los hilos abiertos que inicié en el merge request !15"
- "Publica mi revisión en borrador"

## Cómo llamarlo

- **Dinámica**, la superficie predeterminada: llama a `gitlab_execute_action` con `action` igual al ID de la acción, como `mr_review.changes_get`, y sus parámetros en `params`. `gitlab_find_action` encuentra un ID a partir de una descripción de la tarea.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): llama a `gitlab_mr_review` con `action` igual al nombre de la acción, como `changes_get`, y sus parámetros en `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): llama a la herramienta propia de la acción, como `gitlab_mr_changes_get`, pasándole directamente sus parámetros.

## Disponibilidad

Todos los niveles sirven el grupo completo, tanto en instancias autogestionadas como en GitLab.com.

Acciones de solo lectura: 10 de 23, las que conserva un despliegue en modo de solo lectura.

### `mr_review.changes_get`

> Get the current file diffs (changes) for a merge request. Returns: per-file diffs with old_path, new_path, diff content, file status (added/deleted/renamed), file modes, and truncated_files when GitLab collapses large diffs. See also: [`mr_review.diff_versions_list`](#mr_reviewdiff_versions_list), [`mr_review.raw_diffs`](#mr_reviewraw_diffs), [`merge_request.get`](/gitlab-mcp-server/reference/tools/merge-request/#merge_requestget).

- **Meta-herramienta**: `gitlab_mr_review`, acción `changes_get`
- **Herramienta individual**: `gitlab_mr_changes_get`
- **Nivel**: Free
- **Comportamiento**: solo lectura, idempotente

| Parámetro           | Tipo                     | Requerido | Descripción                                                                                                                                       |
| ------------------- | ------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `merge_request_iid` | `integer`                | sí        | Merge request internal ID                                                                                                                         |
| `project_id`        | `string/integer`         | sí        | Project ID or URL-encoded path                                                                                                                    |
| `order_by`          | `string`                 | no        | For keyset pagination, the column to order results by                                                                                             |
| `page`              | `integer`                | no        | Page number to fetch, 1-based. Defaults to 1. Use the next_page field from the previous response to paginate forward.                             |
| `page_token`        | `string`                 | no        | Keyset pagination cursor: record id at which to fetch the next page, taken from the previous keyset response. Only used when pagination='keyset'. |
| `pagination`        | `string`                 | no        | Pagination method: 'keyset' for keyset-based pagination on large ordered result sets, or 'offset' (the default). Keyset avoids deep-offset cost.  |
| `per_page`          | `integer`                | no        | Items per page. Defaults to 20, minimum 1, maximum 100. Use 100 to minimize round trips when the result set is large.                             |
| `sort`              | `string` (`asc`, `desc`) | no        | Sort order for keyset pagination: 'asc' or 'desc'                                                                                                 |
| `unidiff`           | `boolean`                | no        | Return diffs in unified diff format (default: false)                                                                                              |
