Los usuarios empresariales son las cuentas que posee un grupo de nivel superior, normalmente porque el dominio de su correo está verificado para el grupo. Estas acciones los listan y los leen, desactivan la autenticación en dos pasos de un usuario y borran uno.

## Preguntas de ejemplo

- "Lista los usuarios empresariales del grupo acme"
- "Desactiva la autenticación en dos pasos del usuario empresarial 42"
- "Muestra el usuario empresarial alice"

## Cómo llamarlo

- **Dinámica**, la superficie predeterminada: llama a `gitlab_execute_action` con `action` igual al ID de la acción, como `enterprise_user.delete`, y sus parámetros en `params`. `gitlab_find_action` encuentra un ID a partir de una descripción de la tarea.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): llama a `gitlab_enterprise_user` con `action` igual al nombre de la acción, como `delete`, y sus parámetros en `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): llama a la herramienta propia de la acción, como `gitlab_delete_enterprise_user`, pasándole directamente sus parámetros.

## Disponibilidad

Cuántas de estas acciones sirve una instancia en cada nivel, de un total de 4:

- **Free**: 0
- **Premium**: 4
- **Ultimate**: 4

Solo se lista para un token que tenga `admin_mode`: el servidor quita el grupo de todas las superficies a un token cuyos ámbitos conoce y que no lo tiene.

Acciones de solo lectura: 2 de 4, las que conserva un despliegue en modo de solo lectura.

## Acciones

La descripción de cada acción, y la de cada uno de sus parámetros, es el texto que sirve el servidor para ella en la superficie predeterminada, citado tal cual; por eso está en inglés. Una acción destructiva solo se ejecuta una vez confirmada, salvo que `GITLAB_MCP_YOLO_MODE` (o `AUTOPILOT`) se salte ese paso: la superficie dinámica necesita `confirm: true` en `gitlab_execute_action`, y las otras dos aceptan un parámetro `confirm` o la pregunta del cliente ([Acciones destructivas](/gitlab-mcp-server/operations/security/#acciones-destructivas)).

### `enterprise_user.delete`

> Delete an enterprise user, optionally with hard_delete. Returns: a success confirmation naming the user and group. See also: [`enterprise_user.get`](#enterprise_userget), [`enterprise_user.list`](#enterprise_userlist), [`enterprise_user.disable_2fa`](#enterprise_userdisable_2fa).

- **Meta-herramienta**: `gitlab_enterprise_user`, acción `delete`
- **Herramienta individual**: `gitlab_delete_enterprise_user`
- **Nivel**: Premium
- **Comportamiento**: escribe, destructiva (necesita confirmación), idempotente

| Parámetro     | Tipo             | Requerido | Descripción                                    |
| ------------- | ---------------- | --------- | ---------------------------------------------- |
| `group_id`    | `string/integer` | sí        | Group ID or URL-encoded path                   |
| `user_id`     | `integer`        | sí        | User ID                                        |
| `hard_delete` | `boolean`        | no        | Permanently delete user instead of soft delete |
