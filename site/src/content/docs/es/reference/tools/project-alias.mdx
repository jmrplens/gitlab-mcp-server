Un alias de proyecto es un nombre corto que un administrador da a un proyecto, por el que git clona el proyecto. Estas acciones listan los alias, leen uno, crean uno y borran uno, y son acciones de administrador.

## Preguntas de ejemplo

- "Lista los alias de proyecto"
- "Crea el alias gitlab para el proyecto 42"
- "Borra el alias legacy-api"

## Cómo llamarlo

- **Dinámica**, la superficie predeterminada: llama a `gitlab_execute_action` con `action` igual al ID de la acción, como `project_alias.create`, y sus parámetros en `params`. `gitlab_find_action` encuentra un ID a partir de una descripción de la tarea.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): llama a `gitlab_project_alias` con `action` igual al nombre de la acción, como `create`, y sus parámetros en `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): llama a la herramienta propia de la acción, como `gitlab_create_project_alias`, pasándole directamente sus parámetros.

## Disponibilidad

Cuántas de estas acciones sirve una instancia en cada nivel, de un total de 4:

- **Free**: 0
- **Premium**: 4
- **Ultimate**: 4

Solo se lista para un token que tenga `admin_mode`: el servidor quita el grupo de todas las superficies a un token cuyos ámbitos conoce y que no lo tiene.

Acciones de solo lectura: 2 de 4, las que conserva un despliegue en modo de solo lectura. A un token con `read_api` y sin `api` se le sirven 2 de las 4.

## Acciones

La descripción de cada acción, y la de cada uno de sus parámetros, es el texto que sirve el servidor para ella en la superficie predeterminada, citado tal cual; por eso está en inglés. Las líneas de token dicen lo que exige GitLab 19.4.1 a un token para las peticiones que envía cada acción; en una instancia con Admin Mode activado, una acción que solo puede ejecutar un administrador necesita además `admin_mode`. Una acción destructiva solo se ejecuta una vez confirmada, salvo que `GITLAB_MCP_YOLO_MODE` (o `AUTOPILOT`) se salte ese paso: la superficie dinámica necesita `confirm: true` en `gitlab_execute_action`, y las otras dos aceptan un parámetro `confirm` o la pregunta del cliente ([Acciones destructivas](/gitlab-mcp-server/operations/security/#acciones-destructivas)).

### `project_alias.create`

> Create a project alias mapping a unique name to a numeric project_id (admin-only). Returns: the created alias with id, project_id, and name. See also: [`project_alias.list`](#project_aliaslist), [`project_alias.get`](#project_aliasget), [`project_alias.delete`](#project_aliasdelete).

- **Meta-herramienta**: `gitlab_project_alias`, acción `create`
- **Herramienta individual**: `gitlab_create_project_alias`
- **Nivel**: Premium
- **Token clásico u OAuth**: `api`; este servidor solo lista el grupo a un token que lleve además `admin_mode`
- **Token de grano fino**: Alias: Create en instancia ([página de permisos](/gitlab-mcp-server/reference/fine-grained-permissions/#project_alias))
- **Comportamiento**: escribe, no idempotente

| Parámetro    | Tipo      | Requerido | Descripción                     |
| ------------ | --------- | --------- | ------------------------------- |
| `name`       | `string`  | sí        | The alias name to create        |
| `project_id` | `integer` | sí        | The numeric project ID to alias |
