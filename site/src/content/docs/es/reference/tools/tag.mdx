Gestión de tags de un proyecto: listar, leer, crear y borrar tags, leer la firma GPG o X.509 de un tag, y proteger patrones de tag con el nivel de acceso que puede crearlos, para después leer o quitar esa protección. Borrar un tag borra también la release asociada a él.

## Preguntas de ejemplo

- "Lista los tags del proyecto 42"
- "Crea el tag v2.0.0 en main"
- "¿Está firmado el tag v1.9.0?"

## Cómo llamarlo

- **Dinámica**, la superficie predeterminada: llama a `gitlab_execute_action` con `action` igual al ID de la acción, como `tag.create`, y sus parámetros en `params`. `gitlab_find_action` encuentra un ID a partir de una descripción de la tarea.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): llama a `gitlab_tag` con `action` igual al nombre de la acción, como `create`, y sus parámetros en `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): llama a la herramienta propia de la acción, como `gitlab_tag_create`, pasándole directamente sus parámetros.

## Disponibilidad

Todos los niveles sirven el grupo completo, tanto en instancias autogestionadas como en GitLab.com.

Acciones de solo lectura: 5 de 9, las que conserva un despliegue en modo de solo lectura. A un token con `read_api` y sin `api` se le sirven 5 de las 9.

## Acciones

La descripción de cada acción, y la de cada uno de sus parámetros, es el texto que sirve el servidor para ella en la superficie predeterminada, citado tal cual; por eso está en inglés. Las líneas de token dicen lo que exige GitLab 19.4.1 a un token para las peticiones que envía cada acción; en una instancia con Admin Mode activado, una acción que solo puede ejecutar un administrador necesita además `admin_mode`. Una acción destructiva solo se ejecuta una vez confirmada, salvo que `GITLAB_MCP_YOLO_MODE` (o `AUTOPILOT`) se salte ese paso: la superficie dinámica necesita `confirm: true` en `gitlab_execute_action`, y las otras dos aceptan un parámetro `confirm` o la pregunta del cliente ([Acciones destructivas](/gitlab-mcp-server/operations/security/#acciones-destructivas)).

### `tag.create`

> Create a new tag in a project pointing at a ref. Returns: the created tag with target, message, protection flag, and the associated commit object. See also: [`tag.get`](#tagget), [`tag.delete`](#tagdelete), [`release.create`](/gitlab-mcp-server/reference/tools/release/#releasecreate).

- **Meta-herramienta**: `gitlab_tag`, acción `create`
- **Herramienta individual**: `gitlab_tag_create`
- **Nivel**: Free
- **Token clásico u OAuth**: `api`
- **Token de grano fino**: Repository Tag: Create en proyecto ([página de permisos](/gitlab-mcp-server/reference/fine-grained-permissions/#tag))
- **Comportamiento**: escribe, no idempotente

| Parámetro    | Tipo             | Requerido | Descripción                                                    |
| ------------ | ---------------- | --------- | -------------------------------------------------------------- |
| `project_id` | `string/integer` | sí        | Project ID or URL-encoded path                                 |
| `ref`        | `string`         | sí        | Commit SHA, branch name, or another tag to create the tag from |
| `tag_name`   | `string`         | sí        | Name of the tag                                                |
| `message`    | `string`         | no        | Creates an annotated tag with this message                     |
