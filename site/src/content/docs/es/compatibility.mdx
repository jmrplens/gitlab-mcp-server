## Compatibilidad con ediciones de GitLab

GitLab MCP Server funciona tanto con Community Edition (CE) como con Enterprise Edition (EE). El catálogo Enterprise/Premium desbloquea 16 meta-herramientas adicionales exclusivas de Enterprise: establece `GITLAB_TIER=premium` (o `GITLAB_TIER=ultimate`) en modo stdio, usa `--tier=premium`/`--tier=ultimate` en modo HTTP, o confía en la autodetección desde `GET /license` (por defecto `free`). Los flags heredados `GITLAB_ENTERPRISE=true` (stdio) y `--enterprise` (HTTP) siguen respetándose por compatibilidad, pero están deprecados.

| Funcionalidad                                       | Community (CE) | Enterprise (EE) |
| --------------------------------------------------- | :------------: | :-------------: |
| Proyectos, Issues, MRs, Pipelines, CI/CD            |       ✅       |       ✅        |
| Wikis, Etiquetas, Hitos, Releases                   |       ✅       |       ✅        |
| Usuarios, Grupos, Miembros, Búsqueda                |       ✅       |       ✅        |
| Despliegues, Entornos, Paquetes                     |       ✅       |       ✅        |
| {stats.meta.base} meta-herramientas base            |       ✅       |       ✅        |
| {stats.resources} recursos, {stats.prompts} prompts |       ✅       |       ✅        |
| Merge Trains                                        |       ❌       |       ✅        |
| Métricas DORA                                       |       ❌       |       ✅        |
| Gestión de vulnerabilidades                         |       ❌       |       ✅        |
| Eventos de auditoría                                |       ❌       |       ✅        |
| Políticas de cumplimiento                           |       ❌       |       ✅        |
| +16 meta-herramientas enterprise                    |       ✖        |       ✅        |

Para habilitar funcionalidades enterprise en modo stdio, establece `GITLAB_TIER=premium` o `GITLAB_TIER=ultimate`. En modo HTTP, configura `--tier=premium`/`--tier=ultimate` para forzar el catálogo Enterprise/Premium, u omítelo para que el servidor autodetecte CE/EE por entrada token+URL cuando GitLab informe la edición. Los flags heredados `GITLAB_ENTERPRISE=true` (stdio) y `--enterprise` (HTTP) siguen respetándose por compatibilidad.

## Soporte de plataformas

Hay binarios precompilados disponibles para todas las plataformas principales:

| SO      | Arquitectura          | Binario                               |
| ------- | --------------------- | ------------------------------------- |
| Linux   | amd64                 | `gitlab-mcp-server-linux-amd64`       |
| Linux   | arm64                 | `gitlab-mcp-server-linux-arm64`       |
| macOS   | amd64 (Intel)         | `gitlab-mcp-server-darwin-amd64`      |
| macOS   | arm64 (Apple Silicon) | `gitlab-mcp-server-darwin-arm64`      |
| Windows | amd64                 | `gitlab-mcp-server-windows-amd64.exe` |
| Windows | arm64                 | `gitlab-mcp-server-windows-arm64.exe` |

## Compatibilidad con clientes MCP

Cualquier cliente que soporte el transporte stdio del Model Context Protocol puede usar este servidor. Clientes probados:

| Cliente                           | Transporte | Estado |
| --------------------------------- | ---------- | :----: |
| VS Code + GitHub Copilot          | stdio      |   ✅   |
| Claude Desktop                    | stdio      |   ✅   |
| Cursor                            | stdio      |   ✅   |
| Claude Code (CLI)                 | stdio      |   ✅   |
| Windsurf                          | stdio      |   ✅   |
| JetBrains IDEs                    | stdio      |   ✅   |
| Zed                               | stdio      |   ✅   |
| Kiro                              | stdio      |   ✅   |
| Cualquier cliente Streamable HTTP | HTTP       |   ✅   |

Las cifras de {stats.tools.ultimate_self_managed} autoalojadas y {stats.tools.gitlab_com} en GitLab.com son el conjunto expandido de instancias de herramienta distintas. Los recuentos de {stats.meta.base} base, {stats.meta.self_managed_enterprise} autoalojadas y {stats.meta.gitlab_com} en GitLab.com son tamaños del catálogo de meta-herramientas cuyas acciones se expanden a esa superficie individual mayor.
