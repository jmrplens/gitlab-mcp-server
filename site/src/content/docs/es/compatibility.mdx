## Compatibilidad con ediciones de GitLab

GitLab MCP Server funciona tanto con Community Edition (CE) como con Enterprise Edition (EE). El catálogo Enterprise/Premium desbloquea 16 meta-herramientas adicionales exclusivas de Enterprise: establece `GITLAB_TIER=premium` (o `GITLAB_TIER=ultimate`) en modo stdio, usa `--tier=premium`/`--tier=ultimate` en modo HTTP, o confía en la autodetección desde `GET /license` (por defecto `free`). Los flags heredados `GITLAB_ENTERPRISE=true` (stdio) y `--enterprise` (HTTP) siguen respetándose por compatibilidad, pero están deprecados.

| Funcionalidad                                       | Community (CE) | Enterprise (EE) |
| --------------------------------------------------- | :------------: | :-------------: |
| Proyectos, Issues, MRs, Pipelines, CI/CD            |       ✅       |       ✅        |
| Wikis, Etiquetas, Hitos, Releases                   |       ✅       |       ✅        |
| Usuarios, Grupos, Miembros, Búsqueda                |       ✅       |       ✅        |
| Despliegues, Entornos, Paquetes                     |       ✅       |       ✅        |
| {stats.meta.base} meta-herramientas base            |       ✅       |       ✅        |
| {stats.resources} recursos, {stats.prompts} prompts |       ✅       |       ✅        |
| Merge Trains                                        |       ❌       |       ✅        |
| Métricas DORA                                       |       ❌       |       ✅        |
| Gestión de vulnerabilidades                         |       ❌       |       ✅        |
| Eventos de auditoría                                |       ❌       |       ✅        |
| Políticas de cumplimiento                           |       ❌       |       ✅        |
| +16 meta-herramientas enterprise                    |       ❌       |       ✅        |

Para habilitar funcionalidades enterprise en modo stdio, establece `GITLAB_TIER=premium` o `GITLAB_TIER=ultimate`. En modo HTTP, configura `--tier=premium`/`--tier=ultimate` para forzar el catálogo Enterprise/Premium, u omítelo para que el servidor autodetecte CE/EE por entrada token+URL cuando GitLab informe la edición. Los flags heredados `GITLAB_ENTERPRISE=true` (stdio) y `--enterprise` (HTTP) siguen respetándose por compatibilidad.

## Funcionalidades del protocolo MCP

GitLab MCP Server implementa el conjunto completo de capacidades MCP más allá de las herramientas — recursos, prompts, completions, elicitation y notificaciones de progreso — para que los clientes compatibles obtengan datos contextuales, plantillas de prompts y autocompletado de argumentos además de las llamadas a herramientas.

Las cifras de {stats.tools.ultimate_self_managed} autoalojadas y {stats.tools.gitlab_com} en GitLab.com son el conjunto expandido de instancias de herramienta distintas. Los recuentos de {stats.meta.base} base, {stats.meta.self_managed_enterprise} autoalojadas y {stats.meta.gitlab_com} en GitLab.com son tamaños del catálogo de meta-herramientas cuyas acciones se expanden a esa superficie individual mayor.

## Preguntas frecuentes

### ¿GitLab MCP Server funciona con GitLab Community Edition?

Sí. GitLab MCP Server funciona tanto con Community Edition (CE) como con Enterprise Edition (EE). En CE expone el catálogo base completo — {stats.meta.base} meta-herramientas base, {stats.resources} recursos y {stats.prompts} prompts — que cubre proyectos, issues, merge requests, pipelines, CI/CD, wikis, releases, usuarios, grupos, búsqueda, despliegues, entornos y paquetes. Las funcionalidades exclusivas de Enterprise como merge trains, métricas DORA, gestión de vulnerabilidades, eventos de auditoría y políticas de cumplimiento requieren una licencia Premium o Ultimate y no están disponibles en CE.

### ¿Cómo habilito las herramientas Enterprise?

Define el tier de licencia explícitamente o deja que el servidor lo autodetecte. En modo stdio, establece `GITLAB_TIER=premium` o `GITLAB_TIER=ultimate`; en modo HTTP pasa `--tier=premium` o `--tier=ultimate`. Cuando se omite el tier, el servidor autodetecta la edición desde `GET /license` por entrada token+URL, con valor por defecto `free`. Forzar el catálogo Enterprise/Premium añade 16 meta-herramientas exclusivas de Enterprise. Los flags heredados `GITLAB_ENTERPRISE=true` (stdio) y `--enterprise` (HTTP) siguen respetándose por compatibilidad, pero están deprecados.

### ¿Qué sistemas operativos y arquitecturas se admiten?

Hay binarios precompilados disponibles para Linux, macOS y Windows en amd64 y arm64 — seis binarios en total. macOS ofrece compilaciones separadas para Intel (amd64) y Apple Silicon (arm64). Cada plataforma es un binario estático único sin dependencias en tiempo de ejecución.

### ¿Qué clientes MCP son compatibles con GitLab MCP Server?

Cualquier cliente que soporte el Model Context Protocol puede usar GitLab MCP Server. Los clientes stdio probados incluyen VS Code + GitHub Copilot, Claude Desktop, Cursor, Claude Code (CLI), Windsurf, IDEs de JetBrains, Zed y Kiro. Cualquier cliente Streamable HTTP puede conectarse mediante el modo HTTP. El servidor también admite recursos MCP ({stats.resources}), prompts ({stats.prompts}), completions ({stats.completions} tipos de argumento), elicitation y notificaciones de progreso.
