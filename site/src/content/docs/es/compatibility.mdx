## Compatibilidad con ediciones de GitLab

GitLab MCP Server funciona tanto con Community Edition (CE) como con Enterprise Edition (EE). El catálogo Enterprise/Premium desbloquea {stats.meta.self_managed_enterprise - stats.meta.base} dominios adicionales exclusivos de Enterprise, registrados como meta-herramientas extra con `GITLAB_MCP_TOOL_SURFACE=meta`, herramientas `gitlab_*` extra con `GITLAB_MCP_TOOL_SURFACE=individual` y acciones extra del catálogo en la superficie dinámica predeterminada: establece `GITLAB_TIER=premium` (o `GITLAB_TIER=ultimate`) en modo stdio, usa `--tier=premium`/`--tier=ultimate` en modo HTTP, o confía en la autodetección desde `GET /license` (por defecto `free`). La variable de entorno `GITLAB_ENTERPRISE=true`, ya deprecada, se sigue respetando cuando `GITLAB_TIER` no está definida (equivale a `ultimate`) y deja un aviso en el log. En modo HTTP no existe ningún flag `--enterprise`: pasarlo aborta el arranque; usa `--tier`.

| Funcionalidad                                                                          | Community (CE) | Enterprise (EE) |
| -------------------------------------------------------------------------------------- | :------------: | :-------------: |
| Proyectos, Issues, MRs, Pipelines, CI/CD                                               |       ✅        |        ✅        |
| Wikis, Etiquetas, Hitos, Releases                                                      |       ✅        |        ✅        |
| Usuarios, Grupos, Miembros, Búsqueda                                                   |       ✅        |        ✅        |
| Despliegues, Entornos, Paquetes                                                        |       ✅        |        ✅        |
| {stats.meta.base} dominios base (meta-herramientas con `GITLAB_MCP_TOOL_SURFACE=meta`) |       ✅        |        ✅        |
| {stats.resources} recursos, {stats.prompts} prompts                                    |       ✅        |        ✅        |
| Merge Trains                                                                           |       ❌        |        ✅        |
| Métricas DORA                                                                          |       ❌        |        ✅        |
| Gestión de vulnerabilidades                                                            |       ❌        |        ✅        |
| Eventos de auditoría                                                                   |       ❌        |        ✅        |
| Políticas de cumplimiento                                                              |       ❌        |        ✅        |
| +{stats.meta.self_managed_enterprise - stats.meta.base} dominios enterprise            |       ❌        |        ✅        |

Para habilitar funcionalidades enterprise en modo stdio, establece `GITLAB_TIER=premium` o `GITLAB_TIER=ultimate`. En modo HTTP, configura `--tier=premium`/`--tier=ultimate` para forzar el catálogo Enterprise/Premium, u omítelo para que el servidor autodetecte CE/EE por entrada token+URL cuando GitLab informe la edición. La variable deprecada `GITLAB_ENTERPRISE=true` sigue funcionando cuando `GITLAB_TIER` no está definida; no existe ningún flag `--enterprise`, usa `--tier`.

## Soporte de plataformas

Hay binarios precompilados disponibles para todas las plataformas principales:

| SO      | Arquitectura          | Binario                               |
| ------- | --------------------- | ------------------------------------- |
| Linux   | amd64                 | `gitlab-mcp-server-linux-amd64`       |
| Linux   | arm64                 | `gitlab-mcp-server-linux-arm64`       |
| macOS   | amd64 (Intel)         | `gitlab-mcp-server-darwin-amd64`      |
| macOS   | arm64 (Apple Silicon) | `gitlab-mcp-server-darwin-arm64`      |
| Windows | amd64                 | `gitlab-mcp-server-windows-amd64.exe` |
| Windows | arm64                 | `gitlab-mcp-server-windows-arm64.exe` |

Los binarios de Linux son ejecutables independientes de posición enlazados dinámicamente y requieren glibc. En sistemas musl (Alpine), usa la imagen de contenedor `ghcr.io/jmrplens/gitlab-mcp-server`, que se compila contra musl dentro de la propia imagen. Los paquetes npm de Linux declaran `libc: glibc` por la misma razón y se omiten sobre musl a propósito.

### Perfiles de compatibilidad por cliente

La mayoría de los clientes ignoran los campos MCP que no entienden, así que el servidor envía su superficie completa a todos. La única excepción se gestiona automáticamente: las builds de Codex incluidas en ChatGPT.app rechazan resultados cuyas anotaciones de contenido llevan un valor `priority` fraccionario, de modo que cuando una sesión se identifica como Codex el servidor redondea esas prioridades al entero válido más cercano según la especificación. Todo lo demás — anotaciones de audiencia, contenido estructurado, esquemas de salida, iconos — se entrega sin cambios, y ningún otro cliente se ve afectado. Configura `GITLAB_MCP_CLIENT_COMPAT=off` para desactivar la reescritura.

Para Codex, añade el servidor a `~/.codex/config.toml` con pre-aprobación de herramientas — sin ella, Codex pide confirmación en cada herramienta que no sea de solo lectura, y las ejecuciones no interactivas de `codex exec` cancelan esas llamadas:

```toml title="~/.codex/config.toml"
[mcp_servers.gitlab]
command = "/ruta/a/gitlab-mcp-server"
args = ["stdio"]
default_tools_approval_mode = "approve"

[mcp_servers.gitlab.env]
GITLAB_URL = "https://gitlab.example.com"
GITLAB_TOKEN = "glpat-xxxxxxxxxxxxxxxxxxxx"
```

Mantén la superficie de herramientas `dynamic` por defecto para clientes con límites de número de herramientas (Cursor limita cada servidor a 40 herramientas, Windsurf a 100, los clientes basados en OpenAI a 128 por petición) y deja `GITLAB_MCP_META_PARAM_SCHEMA` en su valor por defecto `opaque` para Codex, que recorta silenciosamente los esquemas de herramienta mayores de ~5 KB.

### Validadores de pasarelas MCP

Una pasarela (gateway) MCP valida el catálogo de un servidor antes de admitirlo, con reglas que decide su operador: una pasarela en producción (IBM [mcp-context-forge](https://github.com/IBM/mcp-context-forge) antes de 0.7.0) rechazaba cualquier descripción de herramienta que contuviera un punto y coma. El servidor mantiene todo lo que lista en ASCII puro y sin puntos y coma, en todas las superficies (una clase de caracteres resiste la siguiente regla mejor que una lista de codepoints), y un mecanismo de sustituciones permite a un despliegue cumplir una regla nueva de pasarela sin esperar a una versión:

```bash
# Reescribe descripciones y títulos listados: pares old=new separados por
# comas, aplicados en orden (la barra invertida escapa \, \= \\)
GITLAB_MCP_DESCRIPTION_SUBSTITUTIONS=';=.'
```

La reescritura cubre descripciones y títulos de herramientas, prompts, recursos y plantillas de recursos, incluidas las descripciones incrustadas en los esquemas de herramienta. Los nombres, URIs, restricciones de esquema (`pattern`, `const`, valores de enum, defaults) y los resultados de llamadas a herramientas no se tocan nunca, y un valor mal formado impide arrancar el servidor en lugar de servir un catálogo sin reescribir. Si tu pasarela es mcp-context-forge, actualizar a 0.7.0 o posterior también resuelve el rechazo del punto y coma en el lado de la pasarela ([issue 3770](https://github.com/IBM/mcp-context-forge/issues/3770)).

## Funcionalidades del protocolo MCP

GitLab MCP Server implementa el conjunto completo de capacidades MCP más allá de las herramientas — recursos, prompts, completions, elicitation, notificaciones de progreso y suscripciones a recursos — para que los clientes compatibles obtengan datos contextuales, plantillas de prompts, autocompletado de argumentos y notificaciones de cambio en vivo además de las llamadas a herramientas.

| Capacidad      |                                                                                                                       Soportada                                                                                                                       |
| -------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------: |
| Herramientas   | ✅ (hasta {stats.tools.ultimate_self_managed} autoalojadas Enterprise / {stats.tools.gitlab_com} GitLab.com + Orbit individuales / {stats.meta.base} base, {stats.meta.self_managed_enterprise} autoalojadas, {stats.meta.gitlab_com} GitLab.com meta) |
| Recursos       |                                                                                                                 ✅ ({stats.resources})                                                                                                                 |
| Prompts        |                                                                                                                  ✅ ({stats.prompts})                                                                                                                  |
| Autocompletado |                                                                                                      ✅ ({stats.completions} tipos de argumento)                                                                                                       |
| Elicitación    |                                                                                                                           ✅                                                                                                                           |
| Progreso       |                                                                                                                           ✅                                                                                                                           |
| Suscripciones  |                                                                        ✅ (26 tipos de recurso, [atendidas mediante sondeo](/gitlab-mcp-server/es/capabilities/subscriptions/))                                                                        |

Las cifras de {stats.tools.ultimate_self_managed} autoalojadas y {stats.tools.gitlab_com} en GitLab.com son el conjunto expandido de instancias de herramienta distintas. Los recuentos de {stats.meta.base} base, {stats.meta.self_managed_enterprise} autoalojadas y {stats.meta.gitlab_com} en GitLab.com son tamaños del catálogo de meta-herramientas cuyas acciones se expanden a esa superficie individual mayor.
