GitLab MCP Server es un servidor [Model Context Protocol](https://modelcontextprotocol.io/) independiente y con licencia MIT que expone las API REST v4 y GraphQL de GitLab como herramientas que un asistente de IA puede invocar. Está escrito en Go, se distribuye como un único binario estático y cubre actualmente {stats.tools.free} operaciones en GitLab Community Edition y hasta {stats.tools.gitlab_com} en GitLab.com.

## Por qué existe

La mayoría de integraciones MCP para GitLab exponen una porción curada de la API —lo justo para leer un merge request o abrir un issue— porque una lista de herramientas mantenida a mano es más fácil de mantener coherente. Este proyecto partió de la premisa contraria: generar _toda_ la superficie de la API desde el catálogo, para que ninguna operación falte simplemente porque nadie llegó a añadirla, y que siga funcionando en Community Edition con solo un token de acceso personal.

Eso creó un segundo problema. Un servidor que registra mil herramientas consume más contexto de arranque del que la mayoría de modelos puede permitirse, y por eso la superficie predeterminada son dos herramientas y no mil. El [conjunto de herramientas dinámico](/gitlab-mcp-server/tools/dynamic-tools/) resuelve cualquier operación bajo demanda, y la [página de arquitectura](/gitlab-mcp-server/architecture/) recoge las decisiones de diseño que se derivan de ello.

## Sin afiliación con GitLab Inc

Este es un proyecto de código abierto independiente. No está afiliado ni respaldado por GitLab Inc., ni es operado por ellos, y se comunica con GitLab únicamente a través de las API públicas documentadas. GitLab es una marca registrada de su propietario. GitLab publica su propia integración MCP oficial por separado; consulta la [página de comparación](/gitlab-mcp-server/comparison/) para ver en qué se diferencian.

## Licencia, versionado y releases

El proyecto se publica bajo [licencia MIT](https://github.com/jmrplens/gitlab-mcp-server/blob/main/LICENSE) y sigue versionado semántico. Versión actual: **{stats.version}**.

La versión major va alineada con el major de [`gitlab-org/api/client-go`](https://gitlab.com/gitlab-org/api/client-go), el cliente oficial del API de GitLab sobre el que se construye este servidor: cuando client-go pase a v3, este proyecto pasará a v3 en la misma release, y ahí se retirarán los campos de compatibilidad deprecados mantenidos durante el ciclo v2. El resto de actualizaciones de dependencias se publican como releases minor o patch.

Cada release publica binarios firmados para Linux, macOS y Windows en amd64 y arm64, una imagen de contenedor en GHCR y Docker Hub, y una extensión para Claude Desktop. Las notas de versión y las descargas están en la [página de Releases](https://github.com/jmrplens/gitlab-mcp-server/releases); las firmas de los binarios se verifican con Cosign como se describe en [integridad del release](/gitlab-mcp-server/es/operations/security/).

## Reportar problemas y contribuir

Los errores y las peticiones de funcionalidad van a [GitHub Issues](https://github.com/jmrplens/gitlab-mcp-server/issues). Incluye la salida de `gitlab-mcp-server --version`, el transporte (stdio o HTTP), el `TOOL_SURFACE` en uso y la edición y versión de GitLab a la que te conectas: esos cuatro datos resuelven la mayoría de reportes de inmediato.

**Las vulnerabilidades de seguridad son distintas: no abras un issue público.** Usa [GitHub Security Advisories](https://github.com/jmrplens/gitlab-mcp-server/security/advisories/new), que mantiene el reporte privado hasta que haya corrección. La política completa está en [SECURITY.md](https://github.com/jmrplens/gitlab-mcp-server/blob/main/SECURITY.md).
