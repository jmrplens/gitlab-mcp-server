GitLab MCP Server is an independent, MIT-licensed [Model Context Protocol](https://modelcontextprotocol.io/) server that exposes the GitLab REST v4 and GraphQL APIs as tools an AI assistant can call. It is written in Go, ships as a single self-contained binary, and currently covers {stats.tools.free} operations on GitLab Community Edition and up to {stats.tools.gitlab_com} on GitLab.com.

The [roadmap](/gitlab-mcp-server/roadmap/) says what the project intends to do and not do over the next year.

## Why it exists

Most GitLab MCP integrations expose a curated slice of the API — enough to read a merge request or open an issue — because a hand-maintained tool list is easier to keep coherent. This project started from the opposite premise: generate the _whole_ API surface from the catalog, so an operation is never missing merely because nobody got round to adding it, and keep it working on Community Edition with nothing but a personal access token.

That created a second problem. A server that registers a thousand tools costs more startup context than most models can spare, which is why the default surface is two tools rather than a thousand. The [dynamic toolset](/gitlab-mcp-server/tools/dynamic-tools/) resolves any operation on demand, and the [architecture page](/gitlab-mcp-server/architecture/) records the design decisions that follow from it.

## Not affiliated with GitLab Inc

This is an independent open-source project. It is not affiliated with, endorsed by, or operated by GitLab Inc., and it communicates with GitLab only through the documented public APIs. GitLab is a trademark of its respective owner. GitLab publishes its own official MCP integration separately; see the [comparison page](/gitlab-mcp-server/comparison/) for how the two differ.

## Licence, versioning and releases

The project is released under the [MIT license](https://github.com/jmrplens/gitlab-mcp-server/blob/main/LICENSE) and follows semantic versioning. Current version: **%%VERSION%%**.

The major version tracks the major of [`gitlab-org/api/client-go`](https://gitlab.com/gitlab-org/api/client-go), the official GitLab API client this server is built on. 3.0.0 moved to client-go v3 and removed the compatibility fields kept during the v2 cycle, and the next client-go major will be this project's next major too. Every other dependency update ships as a minor or patch release.

Every release publishes signed binaries for Linux, macOS and Windows on both amd64 and arm64, a container image on GHCR and Docker Hub, and a Claude Desktop extension. Release notes and downloads are on the [Releases page](https://github.com/jmrplens/gitlab-mcp-server/releases); binary signatures can be verified with Cosign as described under [release integrity](/gitlab-mcp-server/operations/security/).

## Upstream contributions

The server is built on GitLab's REST and GraphQL APIs, on [`client-go`](https://gitlab.com/gitlab-org/api/client-go) and on the [MCP Go SDK](https://github.com/modelcontextprotocol/go-sdk). When building it turns up a gap in one of them, the fix goes upstream rather than staying a workaround here, so every other user of those projects gets it too:

- **client-go**: response fields GitLab sends that the SDK's structs did not model, found by holding each struct against what a running GitLab actually sends, and fixes such as a panic decoding an issue with no id ([merge requests](https://gitlab.com/gitlab-org/api/client-go/-/merge_requests?scope=all&state=all&author_username=jmrp)).
- **GitLab**: API documentation and response annotations corrected where they disagreed with what the API sends, a fix so a revoked GPG identity no longer verifies commits, and proposed additions such as cancelling an automatic merge ([merge requests](https://gitlab.com/gitlab-org/gitlab/-/merge_requests?scope=all&state=all&author_username=jmrp)).
- **MCP Go SDK**: protocol conformance fixes around cancellation, protocol version negotiation and the initialize handshake ([pull requests](https://github.com/modelcontextprotocol/go-sdk/pulls?q=is%3Apr+author%3Ajmrplens)).

Every gap is tracked in the [upstream register](https://github.com/jmrplens/gitlab-mcp-server/blob/main/docs/development/upstream-bugs.md): the upstream issue or merge request, whether it has merged and in which release, and the workaround this server carries until it ships.

## Reporting problems and contributing

Bug reports and feature requests belong in [GitHub Issues](https://github.com/jmrplens/gitlab-mcp-server/issues). Include the output of `gitlab-mcp-server --version`, the transport (stdio or HTTP), the `GITLAB_MCP_TOOL_SURFACE` in use, and the GitLab edition and version you connect to: those four facts resolve most reports immediately.

**Security vulnerabilities are different: do not open a public issue.** Use [GitHub Security Advisories](https://github.com/jmrplens/gitlab-mcp-server/security/advisories/new), which keeps the report private until a fix ships. If you cannot use it, email the same information to the maintainer at [mail@jmrp.io](mailto:mail@jmrp.io), encrypted if you can to the OpenPGP key at [github.com/jmrplens.gpg](https://github.com/jmrplens.gpg). The full policy is in [SECURITY.md](https://github.com/jmrplens/gitlab-mcp-server/blob/main/SECURITY.md).

Contributions are welcome as pull requests on GitHub. [CONTRIBUTING.md](https://github.com/jmrplens/gitlab-mcp-server/blob/main/CONTRIBUTING.md) covers the development setup, branch naming, commit conventions and the review process, and the [Code of Conduct](https://github.com/jmrplens/gitlab-mcp-server/blob/main/CODE_OF_CONDUCT.md) ([Contributor Covenant 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/)) applies to every space the project uses. GitHub is the canonical repository; the read-only [mirror on GitLab.com](https://gitlab.com/jmrp/gitlab-mcp-server) exists for discoverability and takes no contributions.

Every commit in a pull request is signed off by its author with a `Signed-off-by` line (`git commit -s`), which certifies the [Developer Certificate of Origin](https://developercertificate.org/): that the author has the right to contribute the change under the project's MIT license. A check in CI refuses a pull request with a commit that is not signed off, and [CONTRIBUTING.md](https://github.com/jmrplens/gitlab-mcp-server/blob/main/CONTRIBUTING.md#developer-certificate-of-origin) says how to sign off commits already made.

To build the server from source, see [Build from source](/gitlab-mcp-server/install/binary/#build-from-source).
