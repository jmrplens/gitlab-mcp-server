Feature flags a project's application reads to switch a feature on gradually: each flag carries strategies (all users, a percentage of users or of rollout, chosen user IDs or a user list), scoped to environments. These actions manage the flags and the user lists a strategy can target. Turning a flag inactive keeps its history; deleting it does not. The instance's own GitLab feature flags are administration actions instead (see [Administration](/gitlab-mcp-server/reference/tools/admin/)).

## Sample questions

- "List the feature flags of project 42"
- "Roll new-checkout out to 25 percent of users in production"
- "Create a user list for the beta testers"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `feature_flags.feature_flag_create`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_feature_flags` with `action` set to the action's name, such as `feature_flag_create`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_feature_flag_create`, with its parameters as the arguments.

## Availability

Every tier serves the whole group, on self-managed instances and on GitLab.com alike.

Read-only actions: 4 of 10, the ones a deployment in read-only mode keeps. A token with `read_api` and not `api` is served 4 of the 10.

## Actions

The description of each action, and of each of its parameters, is the text the server serves for it on the default surface, quoted as served. The token lines say what GitLab 19.4.1 requires of a token for the requests each action sends; on an instance with Admin Mode turned on, an action only an administrator may run also needs `admin_mode`. A destructive action runs only once confirmed, unless `GITLAB_MCP_YOLO_MODE` (or `AUTOPILOT`) skips that step: the dynamic surface needs `confirm: true` on `gitlab_execute_action`, and the other two take a `confirm` parameter or the client's prompt ([Destructive actions](/gitlab-mcp-server/operations/security/#destructive-actions)).

### `feature_flags.feature_flag_create`

> Create a feature flag with optional activation strategies and scopes. Returns: the created flag with active state, version, scopes, and strategies. See also: [`feature_flags.feature_flag_get`](#feature_flagsfeature_flag_get), [`feature_flags.feature_flag_update`](#feature_flagsfeature_flag_update).

- **Meta-tool**: `gitlab_feature_flags`, action `feature_flag_create`
- **Individual tool**: `gitlab_feature_flag_create`
- **Tier**: Free
- **Classic or OAuth token**: `api`
- **Fine-grained token**: Feature Flag: Create at project ([permissions page](/gitlab-mcp-server/reference/fine-grained-permissions/#feature_flags))
- **Behavior**: writes, not idempotent

| Parameter     | Type             | Mandatory | Description                                                                                               |
| ------------- | ---------------- | --------- | --------------------------------------------------------------------------------------------------------- |
| `name`        | `string`         | yes       | Feature flag name                                                                                         |
| `project_id`  | `string/integer` | yes       | Project ID or path                                                                                        |
| `active`      | `boolean`        | no        | Whether the flag is active                                                                                |
| `description` | `string`         | no        | Feature flag description                                                                                  |
| `strategies`  | `object[]`       | no        | Activation strategies for the flag. Each has a name, optional parameters, and optional environment scopes |
| `version`     | `string`         | no        | Version of the feature flag (new_version_flag)                                                            |
