The templates GitLab ships: CI/CD YAML, Dockerfiles, `.gitignore` files and licenses, each listed and read by name, and the project templates of a project or group. `template.lint` validates CI/CD configuration given as text, and `template.lint_project` validates a project's committed `.gitlab-ci.yml`, both without running a pipeline. Every action only reads.

## Sample questions

- "List the CI/CD templates"
- "Show the Go .gitignore template"
- "Validate this .gitlab-ci.yml against project 42"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `template.ci_yml_get`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_template` with `action` set to the action's name, such as `ci_yml_get`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_get_ci_yml_template`, with its parameters as the arguments.

## Availability

Every tier serves the whole group, on self-managed instances and on GitLab.com alike.

Read-only actions: 12 of 12, the ones a deployment in read-only mode keeps. A token with `read_api` and not `api` is served 11 of the 12.
