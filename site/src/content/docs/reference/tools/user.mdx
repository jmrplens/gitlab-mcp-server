The current user and every user an administrator manages: read and list users, create, modify and delete accounts, and block, unblock, ban, unban, activate, deactivate, approve or reject one; SSH and GPG keys and emails, for the current user or for another; personal access tokens and impersonation tokens; the user's status and avatar; activities, memberships, contribution and project events; to-do items; notification settings; namespaces; instance service accounts; and runners created for the user.

Project and group access tokens, deploy tokens and deploy keys are on [Access tokens and credentials](/gitlab-mcp-server/reference/tools/access/).

## Sample questions

- "Who am I logged in as?"
- "List my SSH keys"
- "What are my pending to-do items?"
- "Block user spammer42"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `user.activate`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_user` with `action` set to the action's name, such as `activate`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_activate_user`, with its parameters as the arguments.
