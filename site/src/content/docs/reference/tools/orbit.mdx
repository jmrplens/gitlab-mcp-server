Orbit is GitLab.com's experimental knowledge graph of code and project data. Its six actions are served only to a session connected to GitLab.com at Premium or Ultimate, and all of them read: `orbit.status` checks the service, `orbit.schema` describes the graph, `orbit.dsl` serves the query language, `orbit.query` runs a query, `orbit.tools` lists Orbit's own MCP tools, and `orbit.graph_status` reports the indexing of a namespace or a project. GitLab answers 404 while its `knowledge_graph` feature flag is off for the caller. The [Orbit page](/gitlab-mcp-server/tools/orbit/) explains the workflow.

## Sample questions

- "Is Orbit available for this GitLab.com token?"
- "Show the knowledge graph schema"
- "Has gitlab-org/gitlab finished indexing?"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `orbit.dsl`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_orbit` with `action` set to the action's name, such as `dsl`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_orbit_dsl`, with its parameters as the arguments.

## Availability

How many of these actions an instance serves at each tier, out of a total of 6:

- **Free**: 0
- **Premium**: 0 on a self-managed instance, 6 on GitLab.com
- **Ultimate**: 0 on a self-managed instance, 6 on GitLab.com

Read-only actions: 6 of 6, the ones a deployment in read-only mode keeps. A token with `read_api` and not `api` is served 6 of the 6.

### `orbit.dsl`

> Read the GitLab Orbit (Knowledge Graph) query language GitLab.com compiles queries in, GQL, as Orbit's query command describes it: its grammar and the JSON Schema of its input, or the same as compact text.

- **Meta-tool**: `gitlab_orbit`, action `dsl`
- **Individual tool**: `gitlab_orbit_dsl`
- **Tier**: Premium, GitLab.com only
- **Classic or OAuth token**: `read_api` (or `api`)
- **Fine-grained token**: Orbit: Read at user ([permissions page](/gitlab-mcp-server/reference/fine-grained-permissions/#orbit))
- **Behavior**: read-only, idempotent

| Parameter         | Type     | Mandatory | Description                                                           |
| ----------------- | -------- | --------- | --------------------------------------------------------------------- |
| `response_format` | `string` | no        | Response format: raw or llm (json is read as raw). When omitted, raw. |

### `orbit.graph_status`

> Inspect GitLab Orbit (Knowledge Graph) indexing status for one group or project, by namespace_id, project_id or full_path: whether Orbit is on, the indexing state of each area, the project counts and the indexed items of each domain.

- **Meta-tool**: `gitlab_orbit`, action `graph_status`
- **Individual tool**: `gitlab_orbit_graph_status`
- **Tier**: Premium, GitLab.com only
- **Classic or OAuth token**: `read_api` (or `api`)
- **Fine-grained token**: one of: Group: Read at group; Orbit: Read at user **or** Project: Read at project; Orbit: Read at user **or** Group: Read at group; Orbit: Read at user; Project: Read at project ([permissions page](/gitlab-mcp-server/reference/fine-grained-permissions/#orbit))
- **Behavior**: read-only, idempotent

| Parameter         | Type      | Mandatory | Description                                                                                                                                                |
| ----------------- | --------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `full_path`       | `string`  | no        | Full path of a group or project to inspect, for example gitlab-org/gitlab. Set exactly one scope field.                                                    |
| `namespace_id`    | `integer` | no        | Group ID to inspect. Set exactly one of namespace_id, project_id, or full_path.                                                                            |
| `project_id`      | `integer` | no        | Project ID to inspect. Set exactly one of namespace_id, project_id, or full_path.                                                                          |
| `response_format` | `string`  | no        | Accepted for compatibility: raw, llm or json. GitLab answers this through GraphQL, which has one structured shape, so every value returns the same output. |

### `orbit.query`

> Execute a read-only GitLab Orbit (Knowledge Graph) query in GQL, the language orbit.dsl describes, naming what orbit.schema lists. A query is one MATCH ... RETURN statement sent as text, with at least one node bounded by its id or a literal property, and a refused query is corrected from the message GitLab answers with.

- **Meta-tool**: `gitlab_orbit`, action `query`
- **Individual tool**: `gitlab_orbit_query`
- **Tier**: Premium, GitLab.com only
- **Classic or OAuth token**: `read_api` (or `api`)
- **Fine-grained token**: Orbit: Read at user ([permissions page](/gitlab-mcp-server/reference/fine-grained-permissions/#orbit))
- **Behavior**: read-only, idempotent

| Parameter         | Type            | Mandatory | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | --------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `query`           | `string/object` | yes       | Orbit query as GQL text, the read-only openCypher 9 based language GitLab.com compiles (orbit.dsl describes it). One statement: MATCH pattern \[WHERE predicates\] RETURN projections \[ORDER BY key \[ASC or DESC\]\] \[SKIP n\] \[LIMIT n\]. Label every node and anchor at least one by its id or a literal property, as in MATCH (p:Project \{full_path: 'gitlab-org/gitlab'\}) RETURN p.id, p.full_path LIMIT 1; LIMIT is not a filter. A relationship type follows a colon, -\[:IN_PROJECT\]-\>, and a repeat is bounded, \*1..3 at most. WHERE takes AND and NOT, never OR. count, sum, avg, min and max aggregate, and every other RETURN item groups; alias an aggregate and sort by the alias: RETURN p, count(mr) AS mr_count ORDER BY mr_count DESC. SKIP takes 0 to 10000 and LIMIT 1 to 1000. orbit.schema lists the entities, properties and relationship types a query names. A JSON object is forwarded as written, and GitLab.com refuses it while it reads queries as GQL. GitLab refuses a query it cannot compile with a message naming the fault. |
| `response_format` | `string`        | no        | Response format: raw (structured JSON, the default here), llm (compact text) or gql (the result as a graph pattern table). json is read as raw.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

### `orbit.schema`

> Inspect the GitLab Orbit (Knowledge Graph) schema: domains, node kinds and edge kinds, with the properties of the node kinds named in expand, or the schema as compact text.

- **Meta-tool**: `gitlab_orbit`, action `schema`
- **Individual tool**: `gitlab_orbit_schema`
- **Tier**: Premium, GitLab.com only
- **Classic or OAuth token**: `read_api` (or `api`)
- **Fine-grained token**: one of: Orbit: Read at user **or** no permission ([permissions page](/gitlab-mcp-server/reference/fine-grained-permissions/#orbit))
- **Behavior**: read-only, idempotent

| Parameter         | Type       | Mandatory | Description                                                                                                                   |
| ----------------- | ---------- | --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `expand`          | `string[]` | no        | Node names whose properties to include, for example Project or MergeRequest. Without it, nodes are listed without properties. |
| `format`          | `string`   | no        | Schema response format: raw (structured, the default) or llm (compact text; json is read as raw).                             |
| `response_format` | `string`   | no        | Alias for format. Must match format when both are set.                                                                        |
