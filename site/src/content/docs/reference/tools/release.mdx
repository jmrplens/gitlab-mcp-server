A release wraps a tag with its notes, milestones and downloadable assets. These actions list releases, read one or the latest, create one (for an existing tag or a new one from a ref), update and delete one, and manage the asset links of a release, one at a time or as a batch after a build. Deleting a release keeps its tag.

## Sample questions

- "List the releases of project 42"
- "Create release v2.0.0 with the changelog as notes"
- "Attach the build artifacts to release v2.0.0"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `release.create`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_release` with `action` set to the action's name, such as `create`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_release_create`, with its parameters as the arguments.

## Availability

Every tier serves the whole group, on self-managed instances and on GitLab.com alike.

### `release.create`

> Create a release for a tag, optionally creating the tag from a ref and attaching asset links. Returns: the created release with author, commit, assets, milestones, and _links. See also: [`release.update`](#releaseupdate), [`release.link_create`](#releaselink_create), [`tag.create`](/gitlab-mcp-server/reference/tools/tag/#tagcreate).

- **Meta-tool**: `gitlab_release`, action `create`
- **Individual tool**: `gitlab_release_create`
- **Tier**: Free
- **Behavior**: writes, not idempotent

| Parameter     | Type             | Mandatory | Description                                                                                                          |
| ------------- | ---------------- | --------- | -------------------------------------------------------------------------------------------------------------------- |
| `project_id`  | `string/integer` | yes       | Project ID or URL-encoded path                                                                                       |
| `tag_name`    | `string`         | yes       | Tag name associated with the release                                                                                 |
| `assets`      | `object`         | no        | Asset links to attach to the release at creation time                                                                |
| `description` | `string`         | no        | Release notes (Markdown supported)                                                                                   |
| `milestones`  | `string[]`       | no        | Milestone titles to associate with the release                                                                       |
| `name`        | `string`         | no        | Release title                                                                                                        |
| `ref`         | `string`         | no        | Branch or commit SHA to create tag from when tag_name does not exist. Include this when the prompt says ref/from ref |
| `released_at` | `string`         | no        | Date of the release in ISO 8601 format                                                                               |
| `tag_message` | `string`         | no        | Message to use for the annotated tag (creates annotated tag instead of lightweight)                                  |
