Snippets are pieces of code or text kept outside a repository. Personal snippets belong to the user: list, read, create, update and delete them, read their content or one file of it, list every snippet of the instance (an administrator's), and browse the public ones. Project snippets are the `snippet.project_*` actions. Threaded discussions and notes on a project snippet, and award emoji on a snippet and on its notes, are actions of this group too.

## Sample questions

- "List my snippets"
- "Create a snippet with this script"
- "Show the discussions on snippet 10 of project 42"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `snippet.content`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_snippet` with `action` set to the action's name, such as `content`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_snippet_content`, with its parameters as the arguments.

## Availability

Every tier serves the whole group, on self-managed instances and on GitLab.com alike.

Read-only actions: 17 of 34, the ones a deployment in read-only mode keeps.
