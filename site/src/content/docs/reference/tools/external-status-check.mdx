An external status check sends a project's merge requests to an outside service, which answers with a passed or failed status that can gate the merge. These actions manage a project's checks (list, create, update, delete), list the status of each check on one merge request, set that status, and retry a check that failed.

## Sample questions

- "Which external status checks does project 42 have?"
- "Show the status checks of merge request !15"
- "Retry the failed compliance check on merge request !15"

## How to call it

- **Dynamic**, the default surface: call `gitlab_execute_action` with `action` set to the action's ID, such as `external_status_check.create_project`, and its parameters in `params`. `gitlab_find_action` finds an ID from a description of the task.
- **Meta** (`GITLAB_MCP_TOOL_SURFACE=meta`): call `gitlab_external_status_check` with `action` set to the action's name, such as `create_project`, and its parameters in `params`.
- **Individual** (`GITLAB_MCP_TOOL_SURFACE=individual`): call the action's own tool, such as `gitlab_create_project_external_status_check`, with its parameters as the arguments.
